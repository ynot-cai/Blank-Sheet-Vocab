# 开发规则

> **写作铁律（用户 2026-10-15 强调）：本文写进去的每一句，都必须出自用户说过的话。**
> 用户没有提过的东西——包括任何自主补充的细节、数据、推理出来的要求，自主总结出来的用户的习惯——一律不许记录。。

## 一、版本管理（提示词 01）

- 版本采用 x.x.x 三段式。
- 第一段（大版本）：由用户指定变化。
- 第二段（小版本）：每次用户要求「上传 git 仓库」时加一。
- 第三段（小小版本）：每次与用户的对话手动加一。
- 每当上层版本加一，下层版本清零。
- 该规则最初记录时，本次记为版本 0.0.1。

## 二、文档维护（提示词 01）

- 每次对话都要更新「版本更新日志」。
- 每次小版本更新，都要更新「项目概述」。
- 每次用户说出关于交互和逻辑相关的内容，都要记录到「逻辑与交互要求」；冲突或修改的部分要删除旧内容。
- 「版本更新日志」：比一般日志更详细，不写「完善某某功能」，而写某某功能会出现什么问题、做了什么修改；更新了某某模块，该模块目标实现什么功能，具体架构是什么。
- 「项目概述」：以架构而非日期为组织，说明程序现有框架、现有交互系统和运行逻辑。

## 三、三个文件夹的分工（提示词 01）

- 「已归档」：归档历史。
- 「关于项目」：说明项目现状。
- 「开发必读」：说明项目要求。
- 今后修改或阅读文件时，按「开发规则」执行。

## 四、推送（提示词 01）

- 不要擅自推送至 GitHub。

## 五、不得擅自添加（提示词 05、06）

- 不要在主界面擅自添加用户未提到的任何视觉元素；仅按用户已明确提出的要求进行修改，避免引入额外的装饰或控件。
- 对任何用户未明确说明的参数（颜色、间距、字号、圆角、阴影等），一律以旧版归档实现为准。
