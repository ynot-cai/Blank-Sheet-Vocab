新增两个真打线上的测试：路由冒烟 + 真实用户流程端到端

背景：这次的「同步不了」暴露了一个盲区——本地 353 项自检**全部直接调用处理函数**，
不经过 URL 匹配也不经过 Vercel 的部署映射，所以「前端请求的路径 ≠ 线上真实路径」
这类问题一个都测不出来。补上两个真的打线上后端的测试：

1) npm run test:live —— 接口冒烟（读 src/dao/syncServer.ts 的 API_ROUTES，不手写路径）
   覆盖：路由可达性（防 404）/ 健康检查 / 401 / 非法 spaceKey / 空库拉取 /
   推送拉回 / 空间隔离 / 批量上限 500 / 来源白名单 403 / 清理
   → 线上 20 项全过

2) npm run test:e2e —— 真实用户流程（import src/dao/cloudSync.ts，就是前端用的那份代码）
   覆盖：测试连接 → 首次同步推 3 条 → 换设备拉回 3 条 → 增量同步传到另一台 →
   换同步码隔离 → 后端挂掉不阻断本地 → 清理测试数据
   → 线上 29 项全过

两个入口都配了 scripts/run-live.mjs / run-e2e.mjs：自动识别 Windows 系统代理并加
--use-env-proxy。原因：这台机器开着系统代理 127.0.0.1:7897，PowerShell/curl 会走，
但 Node 的 fetch 默认完全忽略代理，表现为「浏览器能开、curl 能通、Node 超时」。

test:build 第 8 组护栏：校验「前端 API_ROUTES ⇄ api/ 真实文件」一一对应，
并禁止 src/ 里再出现 /api/sync/ 斜杠老写法。

验证：npm test 353 项全过；test:live 20 项全过；test:e2e 29 项全过
