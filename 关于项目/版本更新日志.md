## 版本 0.0.22 —— 收藏对象从「单词」改为「卡片」（删掉单词收藏）+ 卡片视图补齐自己的筛选 / 搜索 / 排序 / 批量编辑工具栏（2026-10-22）

> 用户原话：「请修改单词列表页面中『收藏』相关的交互：将收藏对象从『单词』改为『卡片』，
> 并删除原有的单词收藏功能。同时，我之前要求的卡片筛选、排序等功能目前尚未实现，
> 请按开发必读文档中的具体要求补齐这些功能。」

### 一、收藏：对象从「单词」改为「卡片」

- **会出现什么问题（改之前）**：0.0.20 把收藏做成了**词的属性**
  （`Word.favorite` 字段 + `dao.words.setFavorite` + `WordQuery.favorite`），
  于是「单词」表格里也有星标、筛选区也有「只看收藏」——收藏的是词，不是卡片。
- **做了什么**：
  - **删掉单词收藏**：`Word.favorite` 字段、`dao.words.setFavorite/setFavoriteMany`、
    `WordQuery.favorite`、表格行首的星标、表格视图的「只看收藏」筛选项、单词视图的批量收藏按钮，
    全部移除；
  - **卡片收藏**：新建 `dao/cardFavorites.ts` + IndexedDB v10 新表 `cardFavorites`
    （记录 `{ id, at }`，`id` = 卡片对应的词 id）。星标只出现在**卡片视图**的每张卡上，
    「⋯」菜单里的「收藏这张卡片」与卡片左下角批量条的「批量收藏卡片」都走这张表；
  - 卡片视图的「★ 只看收藏」按**卡片收藏**过滤：因为收藏不是词的字段，
    筛选时把已收藏的卡片 id 作为**白名单**传进查询（`WordQuery.ids`），
    这样分页与「全选筛选结果」的口径仍然一致（不会出现「看到 3 张、全选 500 个」）。
  - 切到「单词」视图时自动关掉「只看收藏」（单词视图里没有收藏概念）；
  - 顶栏统计条（6 个数字）不受影响。
- **实测**：库里 `words` 表的第一条记录已**没有** `favorite` 字段；`cardFavorites` 表存在；
  点卡片星标后变 ★ 且表里多一条记录；「只看收藏」只剩 2 张；切到单词视图没有任何星标、
  表格 6 行变 5 行（默认不含已斩）；回到卡片视图「只看收藏」不再亮。

### 二、卡片视图补齐自己的工具栏（筛选 / 搜索 / 排序 / 批量编辑）

- **会出现什么问题（改之前）**：0.0.20 的卡片视图**借用**单词视图那一排筛选项
  （同一份 `renderListFilters`），所以看起来「卡片界面里没有筛选/排序」；
  而且那一排是给表格设计的（一行挤 8 个控件、还没有结果计数与批量入口）。
- **做了什么**：新建 `ui/pages/list/CardToolbar.ts`，卡片视图现在有**属于它自己的**三行工具栏：
  1. **搜索**（英文 / 中文义项 / 近义词，300ms 防抖）+ **排序**（词优先级 / 背诵顺序 / 复习优先度 /
     创建时间 / 字母序）+ **升/降序** + 重置筛选；
  2. **筛选**：状态 chips（全部 / 未背 / 学习中 / 已背 / 已斩）+ 含已斩开关 +
     来源下拉 + 词优先级下拉 + ★只看收藏 + 只看需拼写；
  3. **批量编辑**：「共 N 张卡片 · 已选 M 张」计数 + 全选本页 + 清空勾选
     （选中后的批量操作仍在底部批量条：批量斩 / 复活 / 优先级 / 拼写 / **收藏卡片** / 未背 / 删除）。
  - 两个视图仍共用同一份 `ListFilterState`，切视图筛选条件不丢；
  - 「全部」chip 只清状态、不动「含已斩」，所以默认状态（不含已斩）下也一定有一颗是亮的；
  - 勾选卡片时工具栏的「已选 M 张」实时更新（`updateSelectionUi` 里同步）。

### 三、实测中发现并修掉的问题

1. **工具栏计数不跟手**：勾选卡片走的是「轻量同步」（只改节点 + 批量条），
   工具栏上的「已选 N 张」一开始不更新。改成在 `updateSelectionUi` 里一并刷新。
2. **「全部」chip 与默认状态对不上**：原来「全部」= 含已斩，而默认 `includeChopped=false`，
   于是初始状态**五颗 chip 一颗都不亮**。改成「全部」只表示不限状态，另设独立的「含已斩」开关。
3. **PowerShell 的 `Set-Content -Encoding UTF8` 又写进了 BOM**：改完 CSS 后复检发现，
   已剥离并确认全库无 BOM（`test:build` 的 BOM 护栏会红）。

> 用户本轮原话：「一、界面小修改 1. 单词卡片上的『x』键移至右上角，与单词平行对齐，位于最左端。
> 2. 完善『中文意思』的修改功能：修复拖动功能未生效（或触发条件过于苛刻）的问题，并支持新增中文意思。
> 二、考核（记忆过程）开发：主体流程沿用旧版，但评分系统全新设计。请务必检查：我提到和未提到的功能、
> 视觉等细节，是否与旧版完全一致。……（触发机制 / 交互流程 / 选取逻辑 / 考核过程 / 数据记录）」

### 一、单词卡的 X 与「中文意思」编辑

- **会出现什么问题（改之前）**：
  1. 白纸页的 X 是额外塞进 `.answer-card` 的一颗绝对定位按钮（`.paper-card-close`，`top:8px; right:10px`），
     它**浮在单词那一行之上**，不是与单词平行；
  2. 义项拖动用的是 HTML5 `draggable`，而义项文字是 `contenteditable` —— 浏览器优先把它当「选文字」，
     `dragstart` 基本不派发；0.0.20 又在文字的 `dragstart` 上写了 `stopPropagation()`，
     等于把唯一的触发路径堵死。用户体感就是「拖不动 / 触发条件过于苛刻」；
  3. 编辑态没有任何「新增中文意思」的入口。
- **做了什么**：
  - 卡片第 1 行改成「单词在最左端 + 中文 +（右上角）X」：新增 `.word-head-main` 承载会换行的单词/中文，
    `.word-head` 本身 `flex-wrap: nowrap`，X `margin-left: auto` 钉在最右端；
    白纸页删掉 `.paper-card-close`，改传 `onClose`，由卡片自己画这颗 X。
  - 拖动改成**指针拖动**：每行左侧一个明确的拖动手柄 ⠿（`pointerdown/move/up`），
    按在文字上仍是编辑/选字、按在手柄或行空白处才拖动；拖动时目标行高亮（`.drop-target`），松手插到目标位置。
  - 新增「＋ 新增中文意思」：追加一行并自动聚焦；保存时把「一个字都没填」的空义项丢掉。
- **实测**：X 与单词同一行（中心差 ≤ 一行高）、贴 head 行最右端、单词在最左端；
  手柄拖到第二行后顺序交换并落库；新增义项后保存得到 3 个义项、顺序与拖动一致。

### 二、考核（记忆过程）—— 按旧版主体流程 + 全新评分

- **会出现什么问题（改之前）**：「再次记忆」是空壳，「背诵设置」里的三项只存值不生效，
  白纸上没有任何考核环节。
- **两种触发**（用户「二」）：
  1. 点 `exam.everyWords` 次「下一个」后**自动**开始一轮；
  2. 点「再次记忆」**主动**开始。
  两个入口都走同一个 `startExamRound()`。
- **考核界面**（用户「二、交互流程」）：
  - 一层纯白的整页（`.exam-page`：`position:fixed; inset:0; background:#fff; z-index:55`，
    高于白纸按钮带 30、低于答案卡 60）；
  - 中央是大号英文（`.memorize-word`，字号/字距照旧版）、**单词下方**是小喇叭（点击朗读一遍作为提示）、
    再下面是**按义项个数**给出的输入框（`Enter` 跳下一格、最后一格再按 `Enter` 提交，旧版做法）、提交按钮；
  - 提交后先显示「评判中…」，拿到分数后弹**旧版那张可编辑单词卡**（带逐格对错对照），
    点卡片外部 / `Enter` / 空格继续下一个词；卡片下方新增一行「得分 x / 5（通过/未通过，阈值 n）· AI 点评」。
- **评分（用户「四」「五」）**：新建 `services/aiScore.ts`
  - 把「英文 + 每个义项（代表义＋近义词）+ 用户按义项顺序填的答案」交给 AI，要回
    `{score:0~5, inputs:[true/false...], comment}`；分数夹到 0~5 的整数、逐格对错补齐到义项个数；
  - AI 不可用（没填密钥 / 网络失败 / 返回不合法）时**不让考核卡死**：退回旧版那套「逐义项完全匹配」的本地判分，
    分数按命中比例折算成 0~5，点评写明「本地判分」。
- **拼写考察**（用户「英译中考核结束后进入拼写考察，完全与旧版相同」）：
  显示全部中文意思（代表义＋近义词，逗号连接）→ 填英文 → **完全匹配**判分（忽略大小写与首尾空格）→
  小喇叭提示 → 弹答案卡（对绿/错红）。「提示后算不算未通过」仍读 `practice.hintFails`（旧版口径）。
- **选取逻辑**（用户「三」，新建纯函数 `core/examSelect.ts`，可被 node 单测）：
  1. 固定个数 `exam.countPerExam`，纸上候选不足则全选；
  2. 按这张纸存档里的 `memorizeCount` 升序分桶、桶内**随机**，依次取；
  3. 被选中且标记「拼写」的词进入拼写名单；「仅拼写」「斩」的词由调用方排除，`spellOnly` 的词单独排拼写考察；
  4. `attrs.examScore` 有数字且 `< exam.scoreThreshold` 的词，即使没被抽到也**强制加考**（按分数从低到高补）。
- **数据记录**（用户「五」）：一轮结束后**直接写库**——
  - 每个考到的词 `attrs.examCount + 1`；有英译中分数的写 `attrs.examScore`；
    分数低于阈值或拼写错的 `failCount / failCountTotal` 各 +1（保持原有失败率口径）；
  - 这张纸存档里的 `memorizeCount[词]` +1（用户要求「记忆次数存入白纸存档」）。
- **「拼写」「仅拼写」「斩」变成真的标记**：卡片上两个按钮显示 `拼写 ✓ / 仅拼写 ✓`，
  点「仅拼写」或「斩」后该词**立即从纸上消失**（`PaperStage.removeWord` 新增），并同步存档的 `shownIds/placements`。
- **设置**：`exam.scoreThreshold`（默认 3，0~5 可调）新增到「背诵设置」；
  「每出现几个单词进行一次考核」「每次考核数」两项从占位变成真正生效；「考核严格程度」仍只是选项（用户：含义后续再定义）。

### 三、实测中发现并修掉的问题

1. **答案卡的「点任意处继续」有坑**：义项的右键菜单挂在 `body` 上，会被当成「卡片外部」——
   0.0.20 修过一次（白纸页），这次答案卡里也做了同样的排除，否则在考核中改义项会把卡关掉。
2. **考核页与白纸按钮的层级**：一开始 `.exam-page` 用了 z-index 90，把答案卡（60）挡住了；
   改成 55（盖住白纸、让答案卡压在上面）。
3. **中途离开白纸页**：`registerCleanup` 里补了 `examHandle.abort()`，否则考核层会一直盖在别的页面上（实测复现）。
4. **进度行位置**：一开始跟着居中的容器走，看起来像飘在页面中间；改成钉在整页左上角（`position:absolute`）。
5. **纯白整页没有出口**：旧版的考核遮罩挂在白纸上，白纸的「保存并退出」等按钮仍然能点（等于随时可中断）；
   改成纯白整页后这些按钮被盖住了，用户被一道题卡住时只能刷新页面（会丢掉整轮记录）。
   补一个右上角「返回白纸」按钮；中断时**已考完的词照常记入数据库**，提示改成「已中断本轮考核：已考完的 N 个词已记录」。
6. **旧版细节补回**：旧版进入记忆环节会按 `practice.autoSpeak`（默认开）**自动朗读一遍**这个单词，
   本版补回（用户没提，按「未提到的细节与旧版一致」处理）。

### 八、实测中发现并顺手修掉的两个显示问题

1. **白纸页右下角第 5 个按钮被底部白条盖住**：白纸是 `position: fixed; inset: 0` 的全屏层，
   而底部白条是 `position: sticky; bottom: 0; z-index: 20`，永远压在上面；实测 860px 高的视口里
   「删除这张纸」整条被盖住、点不到。修法：**全屏练习界面连底部白条一起藏**（顶栏本来就是
   `display: none`），类名 `.footer-hidden`。
2. **换页后新页面停在上一个页面的滚动位置**：实测从「设置 → 音频设置」（长页）滚到底再点「背诵」，
   新页面一进来标题和左栏第一个页签都不见了。原因是 `router` 只清了 `outlet.scrollTop`，
   而本站的滚动在 `window` 上；补一句 `window.scrollTo({top:0,left:0})`。
3. **「自定义尺寸」选不出来（宽高输入框不出现）**：分辨率的当前值是从 `settings.paper` 反推的，
   而「自定义」与某个预设可能指向同一对宽高 —— 先在 1920×1080 档再点「自定义尺寸」，宽高没变，
   反推出来仍是那一档，于是两个输入框永远不出现。改成按**用户的选择**记（页面内 `customChosen`），
   不再按宽高去猜。

### 二、三个历史问题：根因与修法

**① 单词与按钮重叠**
- 根因：旧 `controlsAvoidRect()` 的避让矩形被 `+controlsPadding`（12px）**向内缩**，真实按钮比它大一圈。
- 修法：改成 `avoid = expand(group, +avoidExtraPx)` **向外扩** 8px；手机端可用区下边界收到 `avoid.y`。
- 证据：12 词 × 按钮组，矩形相交计数 **0**（桌面 1280 与手机 390 均 0）。

**② 按钮大小不断变化**
- 根因：按钮自撑宽度（`再背一个 (Enter)` → `下一个` 宽度就变），布点读的却是常量，两者漂移。
- 修法：宽高只由 `PAPER_UI` 决定，经 `applyPaperButtonVars()` 写成 CSS 变量；文字 nowrap + ellipsis，撑不动盒子。
- 证据：点「下一个」前后按钮矩形宽高**完全一致**（误差 < 0.5px）。

**③ 改中文后纸上不立即显示**
- 根因：旧 `buildWordZone()` 把中文文本在建 DOM 时**烘死**，改库不改纸。
- 修法：`PaperStage.refreshWord(word)` 按最新 `senses` 重算中文与义项角标；卡片保存后立刻调用。
- 证据：编辑态改成「改过的中文说明」→ 保存 → 纸上文本确实变了。

## 版本 0.0.5 —— 修掉启动器「窗口一闪就没了」（.cmd 编码事故）（2026-10-15）

### 一、用户报的现象

> 「为什么我点击『启动白纸单词.cmd』跳出个界面然后消失没反应了」

### 二、根因：`.cmd` 被 cmd.exe 按 GBK 解码，**吞掉了换行符**

**这是什么问题**：我用 UTF-8（无 BOM）写了 `.cmd`，但 **`cmd.exe` 是按系统 ANSI 代码页
（这台机器是 936/GBK）逐字节读 `.cmd` 文件的，不是按 UTF-8**。
把文件按 GBK 解码后一眼就能看出事故现场：

```
|title 鐧界焊鍗曡瘝 鈥斺€?鏈湴鍚姩鍣?cd /d "%~dp0"          ← 两行被吞成一行！
|echo   鐧界焊鍗曡瘝  blank-sheet-vocab  鈥斺€?鏈湴鍚姩鍣?echo =====...   ← 又两行并一行
```

**机制**：UTF-8 汉字的某个尾字节落在 0x81–0xFE 区间时，GBK 会把它**和紧跟的 CR(0x0D)
当成一个双字节汉字**——那个换行符就此消失。于是：

1. `title …` 和下一行 `cd /d "%~dp0"` 并成一行 → **`cd` 根本没执行**；
2. 后面的 `if (...)` 多行块被拆散 → **cmd 报语法错，整个脚本当场退出**；
3. 用户看到的就是**窗口一闪就没**。

> ⚠️ 顺带纠正一个常见误解：文件第 2 行的 `chcp 65001` **救不了这个问题**。
> 它改的是**控制台输出**编码，而 cmd 读 `.cmd` 文件用的是**进程启动时的 ANSI 代码页**，
> 两件事完全无关。

### 三、做了什么修改

| 文件 | 改动 |
|---|---|
| `启动白纸单词.cmd` | 改成**纯 ASCII + CRLF**：只做转发，调用 `scripts\start-local.ps1` |
| `启动本地API.cmd` | 同样改成**纯 ASCII + CRLF** |
| `scripts/start-local.ps1` | **新增**：所有带中文的逻辑与提示都搬到这里，文件保存为 **UTF-8 带 BOM**（PowerShell 5.1 认 BOM，中文正常） |

**分工原则**：`.cmd` 负责「能被 cmd 正确解析」（纯 ASCII 才能保证），
`.ps1` 负责「能正确显示中文」（带 BOM 才能保证）。两边各管一件事，互不干扰。

顺带给 `.ps1` 加了一个自检用开关 `BSV_NO_OPEN=1`（设了就不自动开浏览器），
这样自动化验证启动器时不会突然弹出浏览器窗口；正常双击不会设这个变量。

### 四、验证方式（真的跑了一遍，不是只看代码）

| 项 | 手段 | 结果 |
|---|---|---|
| 编码正确性 | 逐字节读三个文件 | `.cmd` 非 ASCII 字节 **0**、裸 LF **0**、CRLF 28/30；`.ps1` BOM **存在** |
| 换行不再被吞 | 用 GBK 解码 `.cmd`，比对行数 | 源与 cmd 视角**行数一致** |
| 真跑启动器 | `cmd /c "启动白纸单词.cmd"`（带 `BSV_NO_OPEN=1`） | 中文提示**正常显示**，三步全过，vite `ready in 361 ms` |
| 前端起来了 | `GET http://127.0.0.1:5173/` | HTTP 200，含 `id="app"`、`/src/main.ts`、标题「白纸单词」 |
| 本地 API 起来了 | `GET http://127.0.0.1:3000/api/health` | HTTP 200 `{"ok":true,"db":"connected"}` |
| 收尾干净 | 验证后关掉两个端口 | 5173 / 3000 均无监听，无残留 node / cmd 进程 |

### 五、写进「开发规则」的教训

`开发必读/开发规则.md` 第五节第 7 条原本只写了「源码 UTF-8 无 BOM，`.ps1` 例外要带 BOM」。
本轮把它扩成一张**按文件类型区分的编码表**，并新增第 8 条专讲 `.cmd`：

- `.cmd`/`.bat` **纯 ASCII + CRLF**，连注释里都不能有中文；
- 中文逻辑一律放进 UTF-8 带 BOM 的 `.ps1`；
- 附**一行自检口令**（数非 ASCII 字节数，必须是 0），改完这两个文件必须跑。

> 这次事故的教训值得单独记一句：**「UTF-8 无 BOM」这条项目规则本身是对的，
> 但它的适用范围是源码文件，不是「所有文件」。** 一个被 cmd.exe 或 PowerShell 直接执行的
> 脚本，编码规则由**执行者**决定，不由项目习惯决定。

### 三、为什么必须有「占位页」（本轮最重要的设计决定）

首页有六个按钮，但其中**五项目前没有实现**：

| 按钮 | 现状 |
|---|---|
| 录入 / 背诵 / 复习 / 单词列表 | 0.0.1 被**归档删除**（模块 04 / 05 / 06 / 08） |

**会出现什么问题（如果不做占位页）**：点这些按钮会走路由兜底**回落首页**。
用户的判断会是「**按钮坏了**」，而真实原因是「**功能被归档了**」——
这两件事必须能分辨，否则排查方向从一开始就是错的。

**做了什么**：这五条路由一律指向一个占位页，它**不伪造任何功能**，
只陈述三件事：① 现在是什么状态（已归档 / 尚未开发）；② 为什么；
③ 出处与恢复方法（指向具体归档文档）。页尾还打印当前路由，排查时一眼看出「按钮跳对了没有」。

### 四、为什么灰栏要批量算优先度（而不是逐个调 `evalPriority`）

「需复习」= 复习优先度 > 100 的词数，得**遍历全库**。而 `evalPriority` 每调一次
都会 `new Function(...)` 一次——预设词库一档就有几千个词，全库可上万，
逐个调会明显卡住首屏。所以新增 `computePriorities()`：
**表达式只校验一次、只编译一次**，然后跑遍全库；单个词算错只跳过它，
不让一个坏数据拖垮整条统计。语义与 `evalPriority` 保持一致（表达式非法时全部按 0）。

### 五、灰栏口径的两处明确（用户已拍板）

   否则学习中的词会在所有计数里**凭空消失**。

## 版本 0.0.1 —— 「删除与归档行动」：程序收敛为『设置页 + 数据层』（2026-10-15）

### 一、背景与目标

用户下达了一份编号清单式的「删除与归档行动」指令，目标是把程序从

（`已归档` / `关于项目` / `开发必读`）。

用户对四处歧义做了明确拍板：

1. 「二期工程」= 知识点精学（`kc`）**整棵子树**，前端 + 服务端接口 + 建表 + 测试 + 样式**全删**；
2. 「从复习/背诵进入后跳出的页面」= **白纸流程整套**（`src/ui/pages/paper/` 五个文件）+ **记忆页**；
3. 「保存个人数据」= 项目外完整快照 + 本地 git 提交 + 删除走回收站；
4. 其余已无入口的页面（录入 / 背诵 / 复习 / 合并 / 关于）**一并归档删除**。

### 二、删掉了什么，以及「为什么非删不可」

#### 2.1 二期工程（知识点精学）整棵子树 —— 96 个文件 / 20,743 行

- **它是什么**：与「单词泛背」并列的第二套子系统。独立表（知识点卡片 / 语境词 /
  题目历史 / 题库 / 二期会话）、独立 DAO、独立云同步调度器与游标、独立路由子树（`#/kc/*` 十一个页面）、
  独立 AI 提示词（录入拆卡 + 出题 + 评分）、独立掌握度算法与优先度表达式引擎。
- **会出现什么问题（删除前）**：两套子系统并存导致大量**同构代码**——
  一期与二期各有一套优先度表达式引擎，且行为不一致（一期的 `activeExpr`
  对非法自定义表达式**没有回退**，非法值会让全库优先度变 0，而二期有回退）。
  这类「看起来一样、实际不一样」的重复实现是后续维护的主要事故源。
- **做了什么修改**：按用户要求**整棵删除**。前端 20+ 文件、`core/kc*`、`dao/kc*`、
  `services/kc*`、`dev/kc*`、`styles/kc.css`、服务端 `api/kc-*.ts` 与 `api/_lib/kc*`、
  14 套 `test-kc*` 测试，全部归档后进回收站。
- **保留了数据的什么**：**浏览器里已有的二期数据没有被主动清除**（见第五节「后果」）。
- **归档位置**：`已归档/01_二期工程_知识点精学.md`（含全部 96 个文件源码）。

#### 2.2 白纸流程（Paper Flow）—— 7 个文件 / 2,890 行

- **它是什么**：「背诵」与「复习」进入后真正展开的那套界面——把本轮词单撒到一张
  白纸上，靠**空间位置 + 语音**建立记忆；同一条流程用三种模式跑（背诵 / 记忆 / 复习），
  内置布点、避让按钮区、逐义项默写、判分、斩与撤销、进度条与组切换。

  用户要求主界面只留「设置」后，这三个入口全部消失，白纸流程变成**不可达代码**。
