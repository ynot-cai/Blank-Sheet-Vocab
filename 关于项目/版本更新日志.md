## 版本 0.0.1 —— 「删除与归档行动」：程序收敛为『设置页 + 数据层』（2026-10-15）

### 一、背景与目标

用户下达了一份编号清单式的「删除与归档行动」指令，目标是把程序从
「一期泛背 + 二期精学」的双子系统应用，**收敛成一个只剩设置页与数据层的最小程序**，
并把拔掉的模块以「完整模块文档」的形式归档，同时建立三套长期文档
（`已归档` / `关于项目` / `开发必读`）。

用户对四处歧义做了明确拍板：

1. 「二期工程」= 知识点精学（`kc`）**整棵子树**，前端 + 服务端接口 + 建表 + 测试 + 样式**全删**；
2. 「从复习/背诵进入后跳出的页面」= **白纸流程整套**（`src/ui/pages/paper/` 五个文件）+ **记忆页**；
3. 「保存个人数据」= 项目外完整快照 + 本地 git 提交 + 删除走回收站；
4. 其余已无入口的页面（录入 / 背诵 / 复习 / 合并 / 关于）**一并归档删除**。

### 二、删掉了什么，以及「为什么非删不可」

#### 2.1 二期工程（知识点精学）整棵子树 —— 96 个文件 / 20,743 行

- **它是什么**：与「单词泛背」并列的第二套子系统。独立表（知识点卡片 / 语境词 /
  题目历史 / 题库 / 二期会话）、独立 DAO、独立云同步调度器与游标、独立路由子树（`#/kc/*` 十一个页面）、
  独立 AI 提示词（录入拆卡 + 出题 + 评分）、独立掌握度算法与优先度表达式引擎。
- **会出现什么问题（删除前）**：两套子系统并存导致大量**同构代码**——
  一期与二期各有一套优先度表达式引擎，且行为不一致（一期的 `activeExpr`
  对非法自定义表达式**没有回退**，非法值会让全库优先度变 0，而二期有回退）。
  这类「看起来一样、实际不一样」的重复实现是后续维护的主要事故源。
- **做了什么修改**：按用户要求**整棵删除**。前端 20+ 文件、`core/kc*`、`dao/kc*`、
  `services/kc*`、`dev/kc*`、`styles/kc.css`、服务端 `api/kc-*.ts` 与 `api/_lib/kc*`、
  14 套 `test-kc*` 测试，全部归档后进回收站。
- **保留了数据的什么**：**浏览器里已有的二期数据没有被主动清除**（见第五节「后果」）。
- **归档位置**：`已归档/01_二期工程_知识点精学.md`（含全部 96 个文件源码）。

#### 2.2 白纸流程（Paper Flow）—— 7 个文件 / 2,890 行

- **它是什么**：「背诵」与「复习」进入后真正展开的那套界面——把本轮词单撒到一张
  白纸上，靠**空间位置 + 语音**建立记忆；同一条流程用三种模式跑（背诵 / 记忆 / 复习），
  内置布点、避让按钮区、逐义项默写、判分、斩与撤销、进度条与组切换。
- **会出现什么问题（删除前）**：它是全项目交互最复杂的一块（`flow.ts` 一个文件 43 KB），
  且**与页面强耦合**——`LearnPage` / `ReviewPage` / `MemorizePage` 都只是它的薄壳。
  用户要求主界面只留「设置」后，这三个入口全部消失，白纸流程变成**不可达代码**。
- **做了什么修改**：`src/ui/pages/paper/` 五个文件 + `styles/paper.css` + `HintButton` 组件，
  归档后删除。
- **归档位置**：`已归档/02_白纸流程_背诵与复习的核心画布.md`。

#### 2.3 其余页面模块（记忆 / 录入 / 背诵 / 复习 / 合并 / 单词列表 / 关于 / 布局调试）

- **会出现什么问题（删除前）**：这些页面在没有入口之后仍然是**可路由的**——
  手输 `#/import`、`#/list` 仍然进得去。留着它们意味着：① 界面边界与用户要求不符；
  ② 它们依赖的服务（解析管线、布点引擎、TTS）会被一起拖着留成死代码；
  ③ `npm run test:build` 的「没有未被任何文件引用的模块」护栏会长期报红。
- **做了什么修改**：逐模块归档后删除（详见 `已归档/04~14` 号文档）。
  其中「单词列表」是用户点名要求归档的功能——它是**查看和访问单词数据**的界面
  （表格 / 卡片 / 筛选 / 批量操作 / 原始来源弹窗），删除后程序内**再没有任何界面能读到词库内容**，
  但 `dao/words.ts` 的查询能力一字未动。

### 三、设置页被砍到三项

- **会出现什么问题（删除前）**：设置页有八个折叠分区（A 星号参数 / B AI 解析 /
  C 画面与纸张 / C2 布局参数 / D 记忆与练习 / E 复习优先度 / F 云同步 / G 数据 / H 语音），
  其中 C2 布局参数带**草稿态**（改了不应用就丢），是历史上「设置页整页渲染失败」这个
  bug 的现场；被删功能对应的设置项留存会让用户以为功能还在。
- **做了什么修改**：只保留 **① 同步 ② AI 接口 ③ 复习优先度计算公式**，
  另按用户允许保留一个**空的「画面设置」分类外壳**（壳内无任何设置项，只有一句指路说明）。
- **⚠️ 关键设计取舍**：被删分区的**设置字段与默认值仍然完整保留在 `core/config.ts` 里**。
  也就是说「界面删了、数据没删」——把分区文件放回、在 `SettingsPage.ts` 的分区数组里加回一行，
  功能立刻恢复，不需要改任何数据。这是刻意的：用户的第 5 条要求是「保留数据层」。
- **删除带来的真实后果**（用户需要知道）：
  - 「数据」分区里的**导出备份 / 从备份恢复 / 清空数据**三个按钮消失了，
    用户暂时**没有办法手动导出备份**。本地文件夹自动备份仍在跑（见 `main.ts`），
    已连接过的文件夹在浏览器重启后仍会弹黄条请求恢复授权。
  - 语音分区消失后，`services/tts` 整块失去调用方，已一并归档删除。
- **归档位置**：`已归档/11_设置页被删除的分区.md`、`已归档/12_语音朗读模块.md`。

### 四、主界面收敛为一个按钮

- **会出现什么问题（删除前）**：主页是五宫格入口 + 词库概览（总词数/未背/学习中/已背/已斩）
  + 未完成会话角标；顶栏有六个入口 + 二期子树的点亮逻辑。
  入口全删后这些都会变成**指向不存在页面的死链接**。
- **做了什么修改**：
  - 顶栏 `NAV` 从 6 项缩到 1 项（只剩「设置」），并删掉二期子树的高亮特判；
  - 路由表从 16 条缩到 2 条（`/home`、`/settings`），`/dev/layout` 一并删除；
  - 主页只剩标题 + 一句说明 + **一个「设置」按钮**。词库概览按要求一并去掉
    （统计数字属于「查看单词数据」，与「归档单词列表」同一条口径）。
- **数据层没有动**：`dao.words.stats()` 等统计接口完整保留，只是主页不再调用。

### 六、文档体系重建（第 9、10 条要求）

- **会出现什么问题（删除前）**：项目根目录堆着 `AI_RULES.md`（只读）、
  `HANDOVER.md`（120 KB 的会话流水）、`docs/` 四份报告、`blank-sheet-vocab-proxy/README.md`。
  其中 `HANDOVER.md` 里的**事实已经过期**（它写的是「IndexedDB v3 四张二期表」，
  实际是 v8 五张），开发者按它读会被误导。
- **做了什么修改**：
  - 全部中文文档**原件**移入 `已归档/原始文档/`（原件保留，不销毁）；
  - 新建三套长期文档：`已归档`（历史）/ `关于项目`（现状）/ `开发必读`（要求）；
  - `AI_RULES.md` 的规则内容**改名并扩充**为 `开发必读/逻辑与交互要求.md`；
    机器自检脚本 `scripts/checkRules.mjs` 与 `api/_dev/test-r4.mjs` **同步改读新路径**
    （否则规则自检会红）。
  - `AI_RULES.md` 与 `scripts/checkRules.mjs` 原来都是**只读属性**，
    本次为改动脚本清掉了 `checkRules.mjs` 的只读位（`AI_RULES.md` 的只读位保留到移档时）。

### 七、工具链与测试链的同步收尾

删掉页面之后，一批「只服务于被删页面」的测试与工具会永久报红。逐项处理：

| 处理 | 对象 | 原因 |
|---|---|---|
| 归档删除 | 17 套 `api/_dev/test-*.mjs` + `kcImportFixture.mjs` | 断言的是被删页面/流程，留着会给「功能没了测试还在」的误导 |
| 改写保留 | `api/_dev/test-r4.mjs` | 删掉指向白纸流程 / 七个斩点 / 块渲染 / 二期提示词的断言，保留规则固化与义项系统断言；规则文件路径改指 `开发必读/逻辑与交互要求.md` |
| 局部删减 | `api/_dev/test-sense-rules.mjs` | 删掉 [9] AI 重新分析整节（它 import 的 `merge/reanalyze.ts` 已归档）与两处 `merge/drafts.ts` 断言 |
| 删路由 | `api/_dev/harness.mjs` | 摘掉二期三个接口与 `tts-proxy` |
| 删路由 | `src/dao/syncServer.ts` 的 `API_ROUTES` | 摘掉 `ttsProxy`（`api/tts-proxy.ts` 已删），否则 `test:build` 的「路由 ↔ 真实文件一一对应」护栏报红 |
| 版本注入改造 | `vite.config.ts` + `src/core/version.ts` + `src/env.d.ts` | 原 `__APP_VERSION__` 是构建时间戳，无法承载三段式语义版本。改为 `__APP_VERSION__` = package.json 的 `version`、`__APP_BUILD__` = 构建时间戳；设置页底部显示 `版本 x.x.x（构建 …）` |
| 脚本清理 | `package.json` | `scripts.test` 从 30 套测试缩到 13 套；`version` 改为 `0.0.1` |

> **为什么 `core/version.ts` 要改造而不是删掉**：它原本的调用方是「关于页」与「footer」，
> 两者都被归档了，它随即成为孤儿（`test:build` 的孤儿护栏会报）。
> 但用户要求建立三段式版本管理，程序里必须有个地方能自报版本 —— 于是把语义版本接进它，
> 并在设置页显示。**孤儿护栏因此重新变绿，且没有引入新的无用模块。**

### 九、本次的架构变动（模块目标）

| 模块 | 目标 | 现有架构 |
|---|---|---|
| 程序整体 | 只保留「设置页 + 数据层」 | 前端：`main.ts` 启动编排 → `App.ts` 顶栏+路由出口 → 两条路由。数据：IndexedDB v8 六张表。后端：5 个 Serverless 函数。 |
