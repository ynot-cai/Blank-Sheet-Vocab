## 版本 0.0.2 —— 归档动作定义成文、本地启动器与快捷方式、全局 `@` 约定；修复规则文件被截断（2026-10-15）

### 一、把「归档」定义成一条可执行的规则（用户第 1 条要求）

**会出现什么问题（改动前）**：「归档」这个动作只在 0.0.1 的行动里被执行过一次，
规则散落在 `开发规则.md` 第三节的几段话里，缺三样关键东西：

1. **没有定义**——没写清「归档 ≠ 备份 ≠ 删除」，后来的人容易把「删掉」当成「归档了」；
2. **没有粒度判据**——不知道多大的东西算「一个模块」，容易把三个模块塞进一份文档；
3. **没有漏项清单**——实践里最容易出事的不是删文件本身，而是**指向它的引用没清干净**
   （死路由、死测试、`API_ROUTES` 里的死接口），0.0.1 就是这么一路踩过来的。

**做了什么修改**：把 `开发必读/开发规则.md` 第三节从 4 小节扩写成 **10 小节**，
并写成一份**可直接整节复制**的独立规则文本：

| 小节 | 内容 |
|---|---|
| 3.0 | 归档的定义（抽出 → 入档 → 拔除 三步）+ 「归档 / 备份 / 删除」对照表 + **一句话判据** |
| 3.1 | 根目录只允许三个文件夹（各自职责） |
| 3.2 | 什么时候必须归档（触发语 + 孤儿模块 + 不用归档的情形） |
| 3.3 | 归档粒度：什么算「一个完整模块」+ **生成物不许归档删除**（`presets.ts` 的教训） |
| 3.4 | 归档文档的必备结构（**元信息九项**一个都不能少，含完整模板） |
| 3.5 | 索引与清单**必须从归档文档解析生成**，不许手写 |
| 3.6 | 删除的五条硬纪律（先归档后删 / 回收站 / 集合相等 / 先备份 / 路径校验） |
| 3.7 | **拔除时还要清掉的 7 类引用**（路由 / 入口 / 再导出 / 样式入口 / 接口表 / 测试链 / 他处断言） |
| 3.8 | 归档完成后必须报告的七件事 |
| 3.9 | 必须同时保证的**三条恢复路径** |

### 二、本地启动器与可点击快捷方式（用户第 2 条要求）

**会出现什么问题（改动前）**：程序要跑起来必须开终端、`cd` 到项目目录、敲 `npm run dev`，
每次都是手工操作；**没有任何可点击的入口**，也不是一个「双击就能用」的东西。

**做了什么修改**：新增两个启动脚本 + 三个快捷方式。

| 新增 | 作用 |
|---|---|
| `启动白纸单词.cmd` | 检查 Node → 缺依赖则 `npm install` → 起本地 API（最小化窗口）→ `npm run dev -- --open`（**等 vite 真正监听成功再开浏览器**，避免「网页打不开」） |
| `启动本地API.cmd` | 单独启动端口 3000 的本地 API（云同步用；纯本地背单词不需要） |
| 桌面 `白纸单词.lnk` | 指向 `启动白纸单词.cmd`，起始目录 = 项目根 |
| 桌面 `白纸单词 项目文件夹.lnk` | 直接打开项目文件夹（`explorer.exe`） |
| `D:\项目\白纸单词.lnk` | 同第一个，放在项目上级目录方便找 |

**验证方式**：实际跑起来后 `GET http://127.0.0.1:5173/` 返回 **HTTP 200**、
`/src/main.ts` 被 vite 编译成功（11,707 字节）、HTML 里 `id="app"` 与 `/src/main.ts` 都在；
验证完已关闭测试服务器，端口 5173 已释放。

**为什么用 `--open` 而不是 `start http://…`**：`start` 会在服务器还没监听时就打开浏览器，
用户看到的是一片「无法访问」。`--open` 由 vite 在监听成功后自己调起浏览器。

### 三、全局约定：数字后缀 `@`（用户指定）

**会出现什么问题（改动前）**：可调参数与硬编码数字在文档与代码里长得一模一样，
读的人分不清「这个 100 是拍死的还是能调的」，改的时候也不知道该不该动。

**做了什么修改**：在 `开发必读/逻辑与交互要求.md` 顶部新增 **`## 0 · 全局书写约定：数字后缀 @`**：
数字带 `@` = 可调且写出的值就是默认值；并要求这类数字**必须集中成常量、不许散在逻辑里**，
注释写明「默认值 + 可调」，文档里一律带 `@` 后缀，测试里不许抄字面量。

## 版本 0.0.1 —— 「删除与归档行动」：程序收敛为『设置页 + 数据层』（2026-10-15）

### 一、背景与目标

用户下达了一份编号清单式的「删除与归档行动」指令，目标是把程序从
「一期泛背 + 二期精学」的双子系统应用，**收敛成一个只剩设置页与数据层的最小程序**，
并把拔掉的模块以「完整模块文档」的形式归档，同时建立三套长期文档
（`已归档` / `关于项目` / `开发必读`）。

用户对四处歧义做了明确拍板：

1. 「二期工程」= 知识点精学（`kc`）**整棵子树**，前端 + 服务端接口 + 建表 + 测试 + 样式**全删**；
2. 「从复习/背诵进入后跳出的页面」= **白纸流程整套**（`src/ui/pages/paper/` 五个文件）+ **记忆页**；
3. 「保存个人数据」= 项目外完整快照 + 本地 git 提交 + 删除走回收站；
4. 其余已无入口的页面（录入 / 背诵 / 复习 / 合并 / 关于）**一并归档删除**。

### 二、删掉了什么，以及「为什么非删不可」

#### 2.1 二期工程（知识点精学）整棵子树 —— 96 个文件 / 20,743 行

- **它是什么**：与「单词泛背」并列的第二套子系统。独立表（知识点卡片 / 语境词 /
  题目历史 / 题库 / 二期会话）、独立 DAO、独立云同步调度器与游标、独立路由子树（`#/kc/*` 十一个页面）、
  独立 AI 提示词（录入拆卡 + 出题 + 评分）、独立掌握度算法与优先度表达式引擎。
- **会出现什么问题（删除前）**：两套子系统并存导致大量**同构代码**——
  一期与二期各有一套优先度表达式引擎，且行为不一致（一期的 `activeExpr`
  对非法自定义表达式**没有回退**，非法值会让全库优先度变 0，而二期有回退）。
  这类「看起来一样、实际不一样」的重复实现是后续维护的主要事故源。
- **做了什么修改**：按用户要求**整棵删除**。前端 20+ 文件、`core/kc*`、`dao/kc*`、
  `services/kc*`、`dev/kc*`、`styles/kc.css`、服务端 `api/kc-*.ts` 与 `api/_lib/kc*`、
  14 套 `test-kc*` 测试，全部归档后进回收站。
- **保留了数据的什么**：**浏览器里已有的二期数据没有被主动清除**（见第五节「后果」）。
- **归档位置**：`已归档/01_二期工程_知识点精学.md`（含全部 96 个文件源码）。

#### 2.2 白纸流程（Paper Flow）—— 7 个文件 / 2,890 行

- **它是什么**：「背诵」与「复习」进入后真正展开的那套界面——把本轮词单撒到一张
  白纸上，靠**空间位置 + 语音**建立记忆；同一条流程用三种模式跑（背诵 / 记忆 / 复习），
  内置布点、避让按钮区、逐义项默写、判分、斩与撤销、进度条与组切换。
- **会出现什么问题（删除前）**：它是全项目交互最复杂的一块（`flow.ts` 一个文件 43 KB），
  且**与页面强耦合**——`LearnPage` / `ReviewPage` / `MemorizePage` 都只是它的薄壳。
  用户要求主界面只留「设置」后，这三个入口全部消失，白纸流程变成**不可达代码**。
- **做了什么修改**：`src/ui/pages/paper/` 五个文件 + `styles/paper.css` + `HintButton` 组件，

### 三、设置页被砍到三项

- **会出现什么问题（删除前）**：设置页有八个折叠分区（A 星号参数 / B AI 解析 /

  bug 的现场；被删功能对应的设置项留存会让用户以为功能还在。
- **做了什么修改**：只保留 **① 同步 ② AI 接口 ③ 复习优先度计算公式**，

  也就是说「界面删了、数据没删」——把分区文件放回、在 `SettingsPage.ts` 的分区数组里加回一行，
  功能立刻恢复，不需要改任何数据。这是刻意的：用户的第 5 条要求是「保留数据层」。

- **归档位置**：`已归档/11_设置页被删除的分区.md`、`已归档/12_语音朗读模块.md`。
