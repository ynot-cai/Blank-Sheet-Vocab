## 一、一句话定位

**白纸单词**：本地离线、单用户的背单词工具。词条可以是单词、短语（`give up`）或缩写（`NASA`）。
数据存在本机浏览器里，可选用云同步在多设备间共用一份数据；服务器**永不接触 AI 密钥**。

它是一个「把复杂度关在笼子里」的项目：技术选型极简（无框架、无 ORM、无状态服务），
但每一处复杂度都配了**注释说明为什么**、**测试守住回归**、**护栏防止重犯**。

## 二、技术框架

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | **无框架 TypeScript + Vite** | 不用 React/Vue。DOM 由 `src/ui/dom.ts` 的 `h()` / `button()` 等工厂函数手工构造。 |
| 路由 | **自写 hash 路由**（`src/ui/router.ts`） | `Map<path, renderFn>` 精确匹配，无动态段（带参数的路由走 query，如 `#/x?id=…`）。未匹配回落到 `/home`。 |
| 状态 | **极简 store**（`src/state/store.ts`） | 一份设置快照 + `emitDataChanged()` / `onDataChanged()` 事件线。 |
| 本地数据 | **IndexedDB**，库名 `blank-sheet-vocab` | 结构定义集中在 `src/core/dbSchema.ts`。 |
| 后端 | **Vercel Serverless Functions**（`api/*.ts`） | 只做同步与转发，5 个函数。 |
| 数据库 | **Turso（libsql）** | 服务端唯一的持久化，SQL 全部集中在 `api/_lib/*Inventory.ts`。 |
| 打包 | Vite（`base: './'`，产物 `dist/`） | `__APP_VERSION__` / `__APP_BUILD__` 构建时注入。 |
| PWA | 自写 Service Worker（`public/sw.js`） | 可添加到主屏幕，离线可用。 |

### 依赖方向（**单向，不许反向**）

```
ui  ──▶  dao  ──▶  core
 │        │
 └────────┴──▶  services ──▶  core
```

- `core/` **不 import** 任何自己的模块以外的东西（避免循环依赖），也不碰 DOM 与 dao。
- 页面**不许**直接用 `indexedDB` / `localStorage`，一律走 `dao/`。
- `src/dao/index.ts` 是 DAO 的统一出口。

## 三、现有交互系统

### 3.1 界面全貌（版本 0.0.1）

程序**只有两个可达页面**：

```
顶栏（.nav）:  [白纸单词]  [设置]
                    │
                    ▼
  #/home      主页：标题 + 一句说明 + 【设置】按钮
  #/settings  设置页：三个折叠分区 + 一个空分类外壳 + 版本行
```

| 路由 | 页面 | 内容 |
|---|---|---|
| `/home` | 主页 | 标题、一句话说明、**唯一一个「设置」按钮** |
| `/settings` | 设置页 | ① 同步 ② AI 接口 ③ 复习优先度计算公式；另有空壳「画面设置」与版本行 |
| 其它 | — | 未注册的 hash 一律回落到 `/home` |

**全局横幅**（挂在 `App.ts` 的 `banner-box`，不占页面）：

1. **本地文件夹权限黄条**：浏览器重启后 File System Access 权限失效时出现，
   点一下恢复自动备份写入（属于数据层，不是设置项）。
2. **同步状态条**：连续失败 3 次转常驻提示；点击可手动重试。
3. **PWA 提示**：新版本提示条、添加到主屏幕引导。

### 3.2 设置页的交互设计

- 每个分区是一个 `<details>`（可展开收起），带 `data-section` 属性。
- **每个分区独立 `try/catch`**：某组渲染失败只把那一组替换成「这一组读不出来了」+ 两个动作
  （重置该分组 / 返回首页），**其他分组照常可用**。
  这是历史事故的产物——曾经有一处分区抛错导致整页只剩一行「页面渲染失败」，用户连出事的那项都碰不到。
- 设置**改动即存**：`patchSettings()` 先同步更新内存缓存与 store（界面立刻生效），再异步落库。
- 空壳「画面设置」保留是为了**位置感**，壳内只有一句指路说明，没有任何控件。

### 3.3 被归档的交互（**现在不可达，源码在 `已归档/`**）

背诵 / 记忆 / 复习（白纸流程）、录入、合并、单词列表、关于页、布局调试页，以及二期知识点的全部页面。
它们的完整源码与「怎么恢复」写在 `已归档/01~16` 号模块文档里。

## 四、运行逻辑

### 4.1 启动顺序（`src/main.ts` 的 `boot()`）

```
① mountErrorBoundary()          装全局错误边界（后面任何一步崩了都不白屏）
② setSettingsCache(DEFAULT_SETTINGS)   先填默认值，保证任何同步调用都有值
③ await openDB()                开库（失败 → 显示「数据库打不开」+ 重试按钮，并提示关掉其它标签页）
④ 载入设置 → setSettingsCache + appStore.set + 备份快照
⑤ localfile.init()              本地文件夹自动备份
⑥ onDataChanged(...)            数据变动 → 备份防抖写 + 云同步防抖同步
⑦ renderApp(root)               挂顶栏 + 横幅 + 路由出口
⑧ scheduleSync()                启动时若开着云同步，悄悄同步一次
⑨ 词库为空时给一句提示
```

**为什么第 ③ 步必须 `await`**：老版本标签页占着库时升级会被 blocked。
不等待的话，后面的 DAO 会在某个具体表上报「object store was not found」，
用户看到的是一句看不懂的 IndexedDB 报错，而不是「关掉其他标签页」这种能照做的提示。

### 4.2 数据存储

| 表 | 主键 | 用途 |
|---|---|---|
| `words` | `id` | 词条（含 `attrs`：优先级、复习计数、失败计数、优先度…） |
| `sources` | `id` | 来源（一次录入 = 一个来源） |
| `settings` | `key` | 设置（单条记录，深合并补默认值） |
| `sessions` | `id` | 学习 / 复习会话（断点续跑的依据） |
| `ttsCache` | `key` | 第三方 TTS 音频缓存（不进备份、不同步） |

- **库版本 v8**，迁移全部写在 `dbSchema.ts` 的 `createSchema()` 里，**每一段都必须幂等**
  （`repairUpgrade()` 会用 `DB_VERSION + 1` 重跑同一段代码）。
- **缺表自愈**：`dbStale.ts` 检测到连接里缺表时抬版本重建，复用同一段迁移代码。
- 词表的数据迁移是「**一次读取、依次改、一次写回**」——拆成多个 `getAll/put` 会让后跑的迁移
  用旧快照覆盖前一个刚写的字段（踩过：把老词的 `priority` 抹掉了）。

### 4.3 云同步

```
本地写操作 → 标脏（updatedAt / dirty 标记）→ emitDataChanged()
                                              ↓
                                   syncScheduler.scheduleSync()（防抖）
                                              ↓
                         syncData 整形 → 扫描待推 → 分批(≤500) POST /api/sync-push
                                              ↓
                              GET /api/sync-pull?since=<游标> → 本地合并
```

- **本地优先**：同步失败只轻提示（连续 3 次转常驻），**绝不阻断任何操作**。
- **空间隔离**：用户自编「同步码」，服务端只存它的 **SHA-256 哈希**；
  每条 SQL 必须带 `WHERE space_key = ?`，SQL 只允许出现在 `api/_lib/*Inventory.ts`。
- **游标**存在 `settings.cloud`（`lastSyncAt` / `lastPushAt`），随设置一起持久化。
- **强制覆盖**两个方向（本机→云端 / 云端→本机）与「清空云端」都在设置页「同步」分区。

### 4.4 复习优先度计算公式（设置页保留项之一）

- 两条路：**预设**（`balanced` / `forgetting` / `failFirst`）与**自定义表达式**，表达式优先。
- 表达式引擎的三层安全边界：
  1. 字符集白名单正则（`ALLOWED_CHARS_RE`）
  2. 标识符必须在变量白名单（`ALLOWED_VARS`）内
  3. **真试算一次**（区分「语法错 / 除零」与「算出来是 0」）
- 求值用 `new Function(...)`，因此上面三层是**唯一**的防线，改这里必须同步改测试。

### 4.5 AI 接口（设置页保留项之一）

- 客户端在 `src/services/ai.ts`，设置项是 `settings.ai`（`proxyUrl` / `baseUrl` / `model` / `key` / `forceProxy`）。
- `api/ai-proxy.ts` 是**无状态转发**：来源白名单、上游主机白名单、流式透传、
  **不连数据库、不写日志、不回显密钥**。
- 密钥只存在用户本机浏览器（R4 第 1 条）。

### 4.6 错误处理哲学

| 场景 | 做法 |
|---|---|
| 启动失败 | 错误边界兜底页，不白屏 |
| 开库失败 | 专门的提示页 + 重试按钮 + 「关掉其它标签页」的可照做提示 |
| 某一设置分区渲染失败 | 只替换该分区，给「重置该分组」自救出口 |
| 同步失败 | 轻提示 → 连续 3 次转常驻；本地功能不受影响 |
| 路由未匹配 | 回落 `/home` |
| 页面渲染抛错 | 路由层 `try/catch`，出口显示错误文本 |
