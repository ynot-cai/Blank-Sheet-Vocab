# 有道 TTS 接入教程

> 这份文档给**用户**看：怎么申请有道 TTS 密钥、怎么在本应用里填、出了问题怎么查。
> 代码实现见 `src/services/tts/youdao.ts`（适配器）与 `api/tts-proxy.ts`（无状态代理）。

---

## 0. 要不要用？（先读这段）

**不用有道也能朗读。** 应用默认走浏览器内置语音（免费、离线、无需任何配置）。

有道 TTS 解决的是「系统语音不好听 / 没有合适的英文音色」这类问题：

| | 浏览器内置语音 | 有道 TTS |
|---|---|---|
| 费用 | 免费 | 按字符计费（有免费体验额度） |
| 需要配置 | 不需要 | 需要申请密钥 |
| 需要联网 | 不需要（本地语音） | 需要 |
| 音色 | 取决于设备（手机/iPad 上通常不错，Windows 上一般） | 词典发音，专为单词设计，稳定好听 |
| 缓存 | 不缓存（本来就是本地合成） | **缓存音频**，第二次朗读秒播、断网也能听 |

建议：先在设置 → H. 语音里点「试听这个语音」听一下系统语音。
觉得能接受就别折腾密钥；觉得难听再去申请有道。

## 1. 申请密钥（约 5 分钟）

1. 打开 <https://ai.youdao.com/>，注册 / 登录。
2. 进入**控制台 → 语音合成**（有的界面叫「语音合成 TTS」）。
3. **创建一个应用**：
   - 应用名称随便填（例如「背单词」）；
   - **接入方式选「API」**；
   - 创建完会给你两个值 —— 这就是下面要用的：
     - **应用 ID**（`appKey`）
     - **应用密钥**（`appSecret`）
4. ⚠️ **确认这个应用绑定了「语音合成」服务**：应用列表里每个应用后面有服务绑定情况。
   没绑定的话调用会返回错误码 **110**（见下面的排错表）。
5. 记一下额度：控制台能看「体验额度 / 剩余量」。用完后会返回 **401 / 411**。

---

## 2. 填进应用

1. 打开应用的**设置 → H. 语音**；
2. 「语音来源」选 **有道 TTS**（选了之后密钥输入框才会出现）；
3. 填 **应用 ID** 与 **应用密钥**；
4. 「发音人」默认是**有梅梅**（词典美式，专为单词发音设计）—— 想听英式可以换成「有莹莹」；
5. 点 **测试朗读** —— 它念一个固定词 `abandon`，能出声就通了。

### 密钥安全（重要）

- 密钥**只存在你这台设备的浏览器里**（localStorage / IndexedDB），**不会上传服务器**；
- 每次朗读时，签名的计算**在浏览器里完成**，发给服务器的只是「已经签好名的表单」；
- 服务器上的代理（`/api/tts-proxy`）只做「原样转发 + 原样返回音频」，**看不到应用密钥**；
- 换设备要重新填（密钥不跟着云同步走 —— 这也是有意为之）。

## 3. 签名算法（想自己写脚本时看）

有道 v3 的签名：

```
sign = SHA256(appKey + input + salt + curtime + appSecret)

其中 input：
  if (q.length > 20)  input = q 的前 10 个字符 + q 的长度 + q 的后 10 个字符
  else                input = q
```

三个**最容易写错**的地方：

1. **拼接用的是 `q` 本身**。`input` 只参与签名计算，**不作为参数发送**；
   发送的 `q` 永远是原文。
2. `q.length` 是**字符数**（JS 里就是 `q.length`）。
3. 生成签名时 `q` **不做 URL encode**；只有发送时才统一编码。

### 用 Node 脚本核对

仓库里有参考实现（只用 Node 标准库，不联网、不发请求）：

```bash
node scripts/youdaoSign.mjs
```

输出形如：

```
输入：
  appKey    = test-app-key
  ...
sign = 1a8fb7b6faa7160dfccefd934b84b38162318b80864962332e9afcb886f260bb
```

再在浏览器控制台（开发模式）执行：

```js
await __selftest.youdaoSignValue()
```

**两个值必须完全一致。** 一个用 Node 的 `crypto`、一个用浏览器的 WebCrypto，
两个独立实现算出同一个哈希，才能证明算法写对了（只测一边等于自己跟自己对答案）。

跑 `await __selftest.youdaoSign()` 会执行 5 条断言（含长文本截断规则与拼接顺序）。

## 4. 常见错误码

| 错误码 | 含义 | 怎么办 |
|---|---|---|
| 108 | 应用 ID 无效 | 检查设置里的「应用 ID」有没有填错 / 多了空格 |
| 110 | 应用未绑定服务 | 去有道控制台给这个应用**绑定「语音合成」** |
| 202 | 签名校验失败 | 「应用密钥」填错（最常见）。用上面的 Node 脚本核对签名 |
| 401 | 余额不足 | 去控制台充值 |
| 411 | 额度用尽 | 体验额度用完了 |

应用里的表现：**不会弹错误框打断你**，只会在设置页的
「上次第三方调用」那一行显示失败原因，并**自动降级到浏览器语音**继续朗读。
连续失败 3 次后，本次会话内不再尝试第三方（避免每次朗读都先等一个超时）。

---

## 5. 缓存

- 合成成功的音频会存进浏览器的 IndexedDB（表名 `ttsCache`）；
- 第二次朗读同一个词是**秒播**，连网络请求都不发；
- **断网也能朗读已缓存的词**；
- 设置页能看到「已缓存 N 条 · 约 X MB」，可以一键清空；
- 缓存**不进备份、不上传云端**（丢了只是重新合成一次）。

缓存键包含：提供方 + 发音人 + 语速 + 变体 + 归一化后的文本。
所以**换发音人或改语速会重新合成**（这是对的：音色不同，音频当然不同）。

---

## 6. 语音变体（正常 + 慢速）

有道不支持 SSML，所以调不了音调。应用用**速度**做一个近似：
「正常 + 慢速」模式下每个词会合成两遍（1.0 与 0.8），朗读时交替使用。

⚠️ 这会**加倍消耗额度**（按字符计费），所以默认是「单一」。

---

## 7. 本地调试（开发者）

代理的上游地址可以用环境变量覆盖（默认是有道官方地址）：

```bash
# .env.local
TTS_TARGET=http://127.0.0.1:4246/ttsapi
```

自动化验收（`npm run test:t4-ui`）就是这么做的：起一个**假的有道服务**，
让代理转发到它 —— 走的是和线上**完全同一条代码路径**，只是上游可控，
不需要真密钥、不消耗额度、不依赖网络。
