### 0.2 一分钟结论

- 这是一个**个人自用、无账号体系、本地优先（Local-first）**的背单词 Web 应用，技术栈刻意保持极简：**Vite + TypeScript + 原生 DOM（无 React/Vue 等框架）+ Vercel Serverless Functions + Turso(libSQL)**。
- 功能分两期：**一期「泛背」**（单词量大、浅层，靠白纸空间位置 + 语音记单词）；**二期「精学」**（知识点少、深层，AI 拆卡 + AI 出题 + AI 评分 + 掌握度算法）。
- 数据主存储是浏览器 **IndexedDB（库名 `blank-sheet-vocab`，版本 8，10 张表）**；云端是可选的**增量同步 + 后写覆盖**，用**用户自编的同步码经 SHA-256 哈希**当身份，服务器**不知道明文同步码**，也**永远不接触 AI 密钥**（项目里叫「方案 B」）。
- 工程化程度远超「个人小项目」：**26 组自动化自检**、产物模拟器（本地复现 Vercel 部署行为）、真 Chrome/CDP 视口验收、UTF-8 BOM 护栏、路由表 ⇄ 文件一一对应护栏。

### 1.2 一期 / 二期的分区（理解全项目的关键）

| | 一期（单词泛背） | 二期（知识点精学） |
|---|---|---|
| 目标 | 量大、浅层：认识一个词的**多个义项** | 量小、深层：掌握一个**语法/搭配知识点** |
| 最小单位 | `Word`（英文 + 义项数组 + 属性） | `KnowledgeCard`（标题 + 摘要 + 块数组 + 考法标签） |
| 考察方式 | 默写（看英文填中文义项）+ 拼写（看中文拼英文） | AI 出题四题型 + AI 按 rubric 评分 |
| 判分 | **本地纯中文义项匹配**（代表义项或近义词命中即通过） | **AI 打分 1~3**，且允许用户手动改分 |
| 算法核心 | 词级优先级（绝对优先）+ 复习优先度表达式 | 掌握度公式（带方向惩罚）+ 复习优先度表达式 |
| 数据 | `words` / `sources` / `sessions` / `settings` | `knowledgeCards` / `kcSessions` / `dailyContextWords` / `examRecords` / `bankQuestions` |
| 云同步 | `/api/sync-pull` + `/api/sync-push` | `/api/kc-list` + `/api/kc-push`（+ 三张小表接口） |
| 两者的连接 | **只有一处**：二期复习流程中途「桥接」跳去一期白纸背 5 个单词 | 同左 |

> **术语｜泛背 vs 精学**：泛背是「见过、能认出来」，靠重复和空间记忆；精学是「讲得清、用得对」，靠结构化的知识点卡片 + 主动输出（造句/填空）来验证。

## 2. 程序架构

### 2.1 整体架构图【代码】

```
┌─ 浏览器（手机 / 平板 / 桌面）────────────────────────────────────────┐
│  Vite 构建的静态站（dist/，Vercel 托管）                              │
│                                                                     │
│  ui/ (原生 DOM，无框架)  ←── state/store（发布订阅）                  │
│      │ 只能通过 dao/ 取数据                                          │
│  dao/ (Promise 化数据出入口)                                          │
│      │                                                              │
│  core/ (纯逻辑：类型/配置/算法/解析/布点/判分)                        │
│      │                                                              │
│  ┌───┴──────────────────────────────────────────────┐               │
│  │ IndexedDB  blank-sheet-vocab v8（10 张表）★主存储 │               │
│  │ localStorage  设置镜像 / 语音解锁标记 / 安装提示    │               │

       │ 后台静默同步（防抖 5s）              │ AI / TTS 调用
       │ 请求头 X-Space-Key = sha256(同步码)  │ ① 浏览器直连（首选）

┌─ Vercel Serverless Functions（api/，Node 运行时，无状态）─────────────┐
│  只做：CORS 处理 → 参数/结构校验 → SQL 或原样转发                      │
│  /api/sync-pull  /api/sync-push  /api/sync-purge  /api/health        │
│  /api/kc-list    /api/kc-push    /api/context-words /api/exam-history │
│  /api/bank-questions                                                 │
│  /api/ai-proxy（★不 import 数据库、不存密钥、不写日志、不缓存）        │

└──────┬────────────────────────────────────┬─────────────────────────┘
       │ @libsql/client                      │ 原样转发（用完即弃）
       ▼                                     ▼

```

> **术语｜本地优先（Local-first）**：所有操作**先写本地**并立刻生效，云端只是后台追赶；同步失败**不阻断任何功能**，只在顶部给一条轻提示。本项目把这条写成了铁律（`AI_RULES.md` R4-4）。
> **术语｜无状态（Serverless Function）**：每次请求可能落在全新实例上，不能依赖进程内状态。所以本项目数据库客户端做「模块级单例」只为省冷启动，`initSchema()` 用 Promise 缓存且**失败即清缓存**让下次重试。

### 2.2 分层与依赖纪律【代码】

| 层 | 目录 | 硬纪律 | 违反的后果 |
|---|---|---|---|
| 纯逻辑 | `core/` | **不碰 DOM、不碰 dao**；`types.ts` / `kcTypes.ts` 甚至不 import 任何自己的模块 | 循环依赖、无法在 Node 里单测 |
| 数据访问 | `dao/` | 页面**只能**通过 dao 取数据；全部返回 Promise | — |
| 服务 | `services/` | 外部世界（AI/文件/TTS）都在这层 | — |
| 界面 | `ui/` | 手写 `h()` 构造 DOM，**无框架、无虚拟 DOM** | — |
| 后端 | `api/` | **所有 SQL 只能出现在 `_lib/inventory*.ts`**，且每条都带 `WHERE space_key = ?` | 空间隔离被绕过 |

> **术语｜分层架构**：把「算什么」「存哪里」「怎么显示」拆成互不认识的层。好处是每一层都能单独测试与替换；代价是需要纪律，否则会被人「顺手」跨层调用而腐化。
> **术语｜循环依赖**：A import B、B 又 import A，ESM 下会得到「一半初始化」的模块。本项目遇到一处真循环（`dao/kc.ts` ⇄ `dao/kcCloud.ts`），解法是**依赖注入**：同步调度器不 import 同步实现，改由 `main.ts` 调 `registerKcSyncRunner()` 注入（`src/main.ts:88`）。

### 2.3 启动时序【代码】

`src/main.ts` 的 `boot()` 顺序（顺序本身有原因）：

1. 挂**错误边界**（`mountErrorBoundary`）——后面任何一步崩了都不白屏；
2. 先把 `DEFAULT_SETTINGS` 填进内存缓存——保证任何同步调用都有值；
3. `#/dev/layout` 短路：**布局调试页完全不碰数据库**（无头浏览器的虚拟时间会打乱 IndexedDB 异步，导致测量抓不到数据）；
4. `await openDB()`——**必须等到**，否则只在某张表上报「object store not found」，用户看到的是看不懂的 IndexedDB 报错而不是「关掉其他标签页」；
5. 读设置 → 写缓存 + store；
6. 注入二期同步实现（避免循环依赖）、注入二期「单调时钟」的读水位实现；
7. 初始化本地文件夹自动备份，并把 `emitDataChanged` 接到「本地备份 + 一期同步 + 二期同步」三条线上；
8. 挂开发自测入口（仅 DEV）；
9. `renderApp()`，启动时静默同步一次；
10. 词库为空时提示「先去录入页加几个词」。

> **术语｜错误边界（Error Boundary）**：把可能抛错的渲染包起来，出错时给一张兜底页而不是白屏。
> **术语｜单调写入时钟**：`core/kcClock.ts`。用 `max(现在, 已推送水位)` 生成 `updatedAt`，防止用户把设备时钟往回调之后，新写的卡片时间戳比游标还旧 → **静默漏推**。

### 2.4 页面地图（路由表）【代码】

路由是**精确匹配的 hash Map**（`src/ui/router.ts`），**不支持动态段**，带参数的路由走 query（如 `#/kc/edit?id=xxx`）。共 **20 条路由** + 兜底 `/home`：

| 分类 | 路由 |
|---|---|
| 一期 | `#/home` `#/import` `#/merge` `#/list` `#/settings` `#/learn` `#/memorize`（无入口，仅保留） `#/review` `#/about` |
| 二期 | `#/kc` `#/kc/import` `#/kc/list` `#/kc/edit` `#/kc/view` `#/kc/study` `#/kc/exam` `#/kc/review` `#/kc/settings` `#/kc/bank` |
| 调试 | `#/dev/layout`（生产也保留，只读测量，顶栏无入口） |

路由切换时会先执行上一页注册的 **cleanup**（`registerCleanup`），因为白纸流程挂了全局 `keydown`、TTS 与定时器，不摘掉会叠加（`router.ts:71-82`）。

> **术语｜hash 路由**：用 URL 的 `#` 之后部分表示页面，切换时**不向服务器发请求**（天然适配纯静态托管）；代价是没有真正的服务端路由。

### 2.5 后端结构【代码】

- **路由名 = 文件名（连字符）**：`api/sync-pull.ts` → `/api/sync-pull`。写成 `/api/sync/pull` 线上 404、表现为「同步不了」——线上真炸过一次。
- 路径的**唯一权威定义**在 `src/dao/syncServer.ts` 的 `API_ROUTES`；`npm run test:build` 有护栏校验「路由表 ⇄ `api/` 真实文件」一一对应。
- 处理函数只用最小的 `ApiRequest/ApiResponse` 接口，**不引 `@vercel/node`**，因此本地脚本可以直接调用它们做测试。
- **部署的代码只能用 `.js` 后缀的相对导入**（`from './_lib/db.js'`）。原因：Vercel 用 Node 类型擦除把 `.ts` 剥成 `.js`，但**不重写 import 路径**。本地由 `api/_dev/loader-hooks.mjs` 把 `.js` 反向映射到 `.ts`，所以测试照样跑。

### 2.6 架构上的三个「刻意的选择」

1. **不用前端框架**：`ui/dom.ts` 提供 `h() / button() / field() / debounce()` 等薄封装。优点是零依赖、包小、无构建魔法；代价是**没有响应式**——数据变了要显式重画（`router.refresh()` / 各页面自己的 `repaint()`），也因此踩过「重画整棵 DOM 后，内层控件还在往已脱离文档的旧节点里画」的 bug（代码注释有记录）。
2. **二期完全独立于一期**：独立表、独立 DAO、独立路由、独立同步游标与调度器实例。好处是二期后端抽风不会让一期也进入「连续失败 3 次」的常驻提示；代价是两套相似代码（一期/二期各有一套优先度表达式引擎）。
3. **不用 ORM、不上云函数框架**：云端 6 张表的 SQL 全部手写并集中在 `api/_lib/*Inventory.ts`，配合「每条必带 `space_key`」的纪律换取可审计性。

### 3.1 用户旅程总览【代码】

   │            ├─▶ 拼写环节（仅对勾了「需拼写」的词）：显示中文 → 拼英文
   │            ├─▶ 「再次记忆」随时可再抽一轮

### 3.2 录入：文本 → 词条【代码】

**入口**：`#/import`，分四个区：

1. **预设词库**（`import/PresetPanel.ts`）：初中/四级/六级/考研/雅思五档，点一下把该档词表**灌进同一个文本框并切到「粘贴」页签**，再走正常解析流程。**刻意不直接入库**——因为预设词表里的中文还是「整串原始释义」，必须过一遍 AI 才符合《资料整理规范》。
2. **来源 + 优先级**：来源（Source）只是「这批词从哪来」的**分组标签**，**没有优先级**；优先级只有一套、挂在词上（P1~P5，5 最高，默认 3）。
3. **粘贴 / 上传**：支持 `.txt/.csv/.md/.tsv`（按纯文本）、`.docx`（mammoth 取纯文本）、`.pdf`（pdfjs 逐页取文本层，**扫描件明确报错劝退，不做 OCR**）；单文件 ≤ 5MB、**串行解析**（避免多 PDF 并发把手机标签页打死）；`.doc` 明确拒绝并建议另存。
4. **解析设置**：每批 20~100 条（默认 50）。**有 AI 密钥走 AI 解析，没有就走规则解析**（离线兜底）。

**规则解析**（`core/parser.ts`）：自动探测字段分隔符（Tab > 连续 2+ 空格 > 逗号 > 单空格）、剥离行首序号、义项按 `；;／/|` 切分，再用 `splitPackedSenses` 把「量纲、维度」这类**打包义项**拆开。

**AI 解析的产出**经过三层清洗（详见 §6.1）：JSON 抽取 → 逐字段结构校验 → 义项归一化（近义词拆包）。

**合并确认页**（`#/merge`）：AI/规则给你一份「草稿」，你可以逐张改英文/音标/例句、编辑义项、采纳「其他来源留下的旧义项」（`rawSources`）、`斩掉此词（不入库）`、`删除这张卡`；也可以 `智能再合并`（每批 100）或 `AI 重新分析义项`。点「确认入库」时：

- 先 `validateWord` 过滤非法条目（英文为空/超 50 字符/含中文、没有一个有效义项、缺来源）；
- **只对「库里已存在且优先级不同」的词弹冲突框**，给三个分支：
  - `insert` 新增一条；
  - `replace` 用本次覆盖（**旧义项进 `rawSources` 留档**）；
  - `keepBoth` 两条都留。

> **术语｜义项（Sense）**：一个词的一个独立含义，如 `bank → 银行 / 河岸` 是两个义项。每个义项有 `text`（**代表义项**）与 `aliases`（近义词/等价写法）。**这是本项目判分的基础**，规则被写进 `AI_RULES.md` R2 并要求 AI 提示词**逐字复制**。
> **术语｜rawSources**：同一个词被第二个来源再次录入时，旧义项不会丢，而是存进 `rawSources`，供列表页手动「采纳」。

### 3.3 「白纸」是什么：核心交互隐喻【代码】

**白纸 = 一整屏白底画布，单词被「随机」撒在上面**，靠**空间位置 + 语音**建立记忆。用户看到的是：每个落点上「英文单词 +（浅灰小数字：义项个数）」，下面一行是中文意思。

- **点单词** → 切换这一行的中文意思显示/隐藏；
- **点中文意思** → 弹出**可编辑的单词卡**（能改义项、标「拼」、斩）；
- **义项个数徽章**只在义项 > 1 时显示（字号 = 单词字号 × 0.5，最小 12px，色 `#bbb`）——因为移动端没有 hover，不能靠悬停发现「这是多义词」；
- 中文只显示每个义项的**代表义项**，`aliases` 一律不显示（一个义项可能七八个近义词，全铺开会糊成一片）；
- 入场动画 `paper-in 0.45s`（缩放 + 淡入），可在设置里整体关闭。

**落点怎么算**（`core/layout.ts`，S3 起是重写过的算法）：

1. `computeGrid()`：由**平均词宽**推导自然格宽（`词宽均值 × 1.15 + 最小空隙`）、行高同理 → `maxCols/maxRows` 由可用面积算出 → `autoCols = round(sqrt(target × 宽高比))`，夹在「设备硬下限（手机 3 / 平板 4 / 桌面 4）」与 `maxCols` 之间 → 手动列数覆盖（`auto/3/4/5/6/8/10`）优先但**受宽度夹住**（若被夹会报 `colsClamped`）→ 格子**撑满**可用区。
2. `layoutWords()`：格子顺序按 **seed 打乱** → 每个词按**自己的**宽高在格内抖动 → ① 夹回纸张边界 ② 与「按钮避让区」用**真实矩形**判交，相交就换格 ③ 仍有重叠则 `resolveOverlaps()` 上下推开（最多 8 轮）→ 输出**归一化坐标**（0~1）。
3. **放不下的词从末尾丢弃**，所以「纸面容量」= 实际返回的落点数（进度条会显示「纸面已满」）。
4. seed = `session.id + '#' + groupIndex` → **同一次会话的位置稳定**，续跑不会跳。

**避让区**：手机上底部有一条圆形按钮横带（整条横带都要避开），平板/桌面只在右下角一个方块内避让。

> **术语｜抖动（jitter）**：在格子里做小幅随机偏移，避免排成呆板的行列——空间记忆需要「位置可区分」。
> **术语｜归一化坐标**：用 0~1 的比例而不是像素存位置，换屏幕尺寸后相对位置不变。
> **术语｜seed / 确定性随机（mulberry32）**：用固定种子产生可复现的伪随机序列。同一次会话必须一致，否则「点了下一步上一个词又回来了」。

**设备三档默认参数**【代码】

| 档位 | 断点 | 边距 | 最小空隙 | 字号 | 目标一屏词数 | 圆按钮(直径/间距/小字) |
|---|---|---|---|---|---|---|
| 手机 | ≤ 767px | 8px | 8px | 16px | 16 | 50 / 16 / 12 |
| 平板 | 768~1024px | 14px | 16px | 22px | 24 | 56 / 18 / 13 |
| 桌面 | > 1024px | 24px | 20px | 24px | 40 | 44 / 12 / 12 |

> 【未确认】手机档「2 列 × 8 行 = 16 个词」是**目标值**（`config.ts` 注释推导），真实容量由几何决定；自检只断言「容量 ≥ 目标」。

### 3.4 记忆环节：判分怎么发生【代码】

点「记忆」后进入**串行逐词**的作答（同一时刻屏幕上只有一个词）：

1. 在原落点弹出一个遮罩（`repositionOverlay` 会把整块卡片夹进视口内），显示**英文题干** + **按生效义项数量生成的 N 个中文输入框**（placeholder「义项 1/2/3…」）；
2. `autoSpeak` 打开时朗读该词；
3. **Enter 行为**：填完一格按 Enter → **跳到下一格**（并全选原内容），**在最后一格按才提交**。这是用户明确要求的口径——旧实现任意一格 Enter 都提交，多义词几乎必然被半途交上去判错；
4. **提交后判分**：第 i 个输入框必须命中某个生效义项——命中 `text`、去掉词性前缀的 `text`、**或任一 `aliases`** 即算对；比较前统一小写并去掉空白与常见标点；**全部框都对**才算这词通过（`answerCorrect = results.every(Boolean)`），空值直接算错；
5. **没有任何时间限制**：`waitUntil()` 会一直等到用户点提交或主动退出。代码注释记录了它曾经是一个**隐蔽的超时自动提交**（400 × 25ms = 10 秒），而 `checkRules.mjs` 按变量名扫（`timeLimit/countdown`）**扫不到它**——这正是 `AI_RULES.md` R1 要禁的东西；
6. 弹出**答案卡**：与普通界面**完全同一张可编辑单词卡** + 逐框的绿 ✓ / 红 ✗ 对照 + 「正确答案」；点卡片外任意处 / `Enter` / `空格` 继续下一个；
7. 「🔊 朗诵一遍」是**唯一**的提示形式（旧版的「首字母 + 长度」字母掩码提示已**删除**而不是停用，注释说明原因：留着早晚会被接回去，而那条路径会直接泄露字母）。是否「用了提示就算未通过」由设置 `practice.hintFails` 决定（**默认不算**），且**只对开启之后的考核生效，不追溯历史**。

**失败与计数的累加时机**（T2 改造的核心）：每一路考察结束都调**同一个** `recordExam(id, passed)`：

- **每次判分**（不论对错）`examDeltas[id] += 1` → 这是**分母**；
- `passed === false` 时额外 `failDeltas[id] += 1` 并加入 `failedIds` → 这是**分子**。

> **为什么必须集中在一个口子**：以前只有「未通过」被记录，**答对的题一点痕迹都不留**，于是「考了多少次」无法还原、失败率无从算起。新增考察环节只要调它就不会漏。

### 3.5 拼写环节【代码】

- **不是另外抽词**，而是「当次记忆选到的词里标了『需拼写』（`attrs.needSpell`）的那些」；
- 题干 = 全部生效义项的 `text + aliases` 用「，」连接（**会显示近义词**，与白纸只显示代表义项不同）；
- 判分：`输入.trim().toLowerCase() === word.en.trim().toLowerCase()`——**忽略大小写与首尾空格，必须完全相等**；
- 同样走 `resolvePass` + `recordExam`；答案卡的对错用**最终判定**（开了「提示算未通过」时，答对也显示为错，否则会出现「绿勾 + 却记了一次未通过」的自相矛盾）；
- 拼写环节**不增加**「已记忆遍数」。

### 3.6 背诵抽词算法（优先级**绝对**优先）【代码】

优先级（`word.priority`，P1~P5）是**唯一**的优先级，且是**绝对优先**：5 的词全部抽完才会抽 4 的，不掺概率。

`sortForLearn(words, samePriorityOrder, seedText)`：先按 `priority` 降序；同级内：

- `'createdAt'`（默认）：**先录入的先背**，可预测、可复核；
- `'random'`：用 `mulberry32(seedFromString(sessionId + '#' + word.id))` 的**确定性**权重打乱（同会话稳定、不同会话不同）。

**「开始背诵」与「再背一个」必须共用同一个排序函数**——两处各写一份的话，用户会看到「我点的顺序和它给我的不一样」，很难查。

**记忆环节抽词** `pickForMemorize()`（规则由用户口头定稿，代码注释里是权威口径）：

1. 候选池 = 本轮词单里**已经在纸上出现过**、且未被斩的词（没上纸的词不进记忆）；
2. 候选 ≤ `memorizeMaxPick`（默认 10）→ **全部抽走**（有几个抽几个）；
3. 候选 > 上限 → 先 `shuffle()` 再**稳定排序**按 `memorizeCount` 升序（遍数最少的先抽），**稳定排序保留了同级之间的随机顺序**——这正是「遍数相同时随机抽」；取前 N 个；
4. **额外项**：`session.lastRoundFailedIds`（**上一轮**未通过）中没被抽到的词**追加**进来 → **总数允许超过上限**。

> ⚠️ 与旧实现的差异（注释明确「别改回去」）：同级**必须随机**；未通过词是**额外追加**而不是「挤掉补位词」；「未通过」的口径**只算上一轮**（否则一个很早以前错过的词会被永远强制抽到）。

### 3.7 复习：怎么决定「先复习哪个」【代码】

**与其他 App 最大的不同：复习不选数量。**（T2 改造）进复习页**直接开始**，底部主按钮是「再复习一个」——点一下多上一个词。原因是「推荐的复习数量」用户无从判断合不合理。

- 首屏一次取 **30 个**（等于旧的默认分组大小 `reviewGroupSize`，习惯不变）；
- `sortReviewCandidates()`：候选 = 已背/学习中且未斩，按**复习优先度降序**，同分时 `lastReviewAt` **更早**（含从未复习）的优先；
- 这一批复习完 → `advanceChunk()` **追加**下一批（追加而不是替换，否则已上纸、已复习过的词会从词单消失、白纸上的位置也没了）；追加时清空 `placements` 重挂流程；
- 「背完了」→ `finishReview()`：**只处理真正上过纸、未斩的词**——写 `lastReviewAt = now`、`reviewCount += 1`、`examCount += 本次增量`，**然后**才算 `reviewPriority`（顺序不能反，否则用旧失败率算）；一个词都没复习到时不写任何记录并提示。

**复习优先度 = 表达式求值**（`core/priority.ts`）。`customExpr` 非空时优先，否则用预设：

| 预设 | 名称 | 表达式 |
|---|---|---|
| `forgetting` | 遗忘曲线型 | `daysSinceReview / (reviewCount + 1) + failRate * 20` |
| `failFirst` | 失败率优先型 | `failRate * 60 + daysSinceReview` |
| `balanced` | **均衡型（默认）** | `daysSinceReview * 0.5 + failRate * 30 + (needSpell ? 2 : 0) + reviewCount * -0.2` |
| `failRateBalanced` | 失败率均衡型 | `failRate * 50 + daysSinceReview * 0.5` |

表达式可用变量：`needSpell / failRate / examCount / failCount / failCountTotal / reviewCount / daysSinceReview / daysSinceLearned / true / false`；没有记录时天数取 **999**（视作很久没复习）。

**`failRate = failCountTotal / examCount`，分母缺失或为 0 时不做除法、直接取默认 0.5**（默认正确率 50%）。注释特意提醒**量纲**：`failRate` 是 0~1 的比率，`failCount` 是次数，同一个系数配在两者上差一两个数量级——所以新预设的系数是**重新标定**的。

> **术语｜表达式引擎（安全的 `eval`）**：本项目允许用户自定义公式，用 `new Function(...)` 求值。安全边界是三层：字符集白名单正则 + 标识符必须在变量白名单内 + **真试算一次**（区分「语法错/除零」与「算出 0」）。非法表达式在二期会**回退预设**；一期 `activeExpr` 只在写入时校验，读到非法值会 warn 并全按 0 处理【代码】，两期行为不一致【未确认是否有意】。
> **术语｜T2 的历史回填**：优先度从「未通过次数」改成「失败率」后，老词没有分母。迁移按用户要求**给老词默认正确率 50%**：`examCount = failCountTotal × 2`（用**不封顶**的真实累计而不是封顶值，否则老词反被降权）；已有数字（含 0）一律跳过以保证**幂等**。

### 3.8 「斩」与「复活」【代码】

- **斩 = 软删除标记 `status = 'chopped'`**（不是墓碑），从此不参与抽词、复习、统计；
- **不弹二次确认**（铁律 R3），但必须给 **≥ 8 秒的撤销 Toast**：`UNDO_WINDOW_MS = 8000`，注释写明「只许调大不许调小」，自检会断言 ≥ 8000；
- 撤销要**完整恢复五件事**：词的状态、词单里的下标、`shownIds`、`placements` 落点、白纸上的元素（还有复习页的分组插回原处）；用 `settled` 标志防「点撤销」与「超时移除」双跑；
- **永久后悔药**：列表页统计条点「已斩」可随时筛选出它们并**复活**；复活状态 = 「背过就 `learned`，没背过就 `unlearned`」；
- **批量斩**也会逐条快照原状态，撤销时逐条还原（不能用「一律设 unlearned」代替）；
- 一期「斩」是 `status='chopped'`；二期「斩」是**墓碑 `deleted=1` + `status='chopped'`**（因为二期要能在「已斩」列表里看到并复活）——两期语义不同，是刻意的。

### 3.9 列表页与设置页【代码】

**列表页**：关键词（同时匹配英文 / 义项文本 / 近义词）、状态多选、来源、只看需拼写、含已斩、`未通过 ≥`、`优先度 ≥`（复习优先度）、**词优先级 P1~P5 精确筛选**；排序支持「词优先级 / 背诵顺序 / 复习优先度 / 创建时间 / 字母序」+ 升降序（`learnOrder` 为 null 的永远排最后）；分页 50/100/200；**批量编辑不设数量上限**（可跨页「全选筛选结果」）：批量斩/复活/设优先级/标记需拼写/设为未背/删除。另有 `重算优先度`（全库重算）与 `清空全部单词`（需手输「删除」两个字，来源保留）。

**设置页**分 A~G 区，关键可调项：

| 参数 | 默认 | 作用 |
|---|---|---|
| `memorizeMaxPick` | 10 | 一次「记忆」最多抽几个（额外项可突破） |
| `memorizeTargetCount` | 1 | 每词至少记忆几次，「背完了」才出现 |
| `memorizeEvery` | 3 | 每背几个新词，「再背一个」按钮变「记忆」 |
| `failCountCap` | 2 | 属性②「未通过次数」的上限（另有内部真实累计不封顶） |
| `reviewGroupSize` | 30 | 复习每组上限【冲突】复习页实际分批用的是常量 `REVIEW_CHUNK = 30`，改这个设置不再改变首屏批量 |
| `paperWordGapFactor` | 2.4 | 纸上单词的间距系数 |
| 布局三档 + 手动列数 | 见 §3.3 | 手机一屏放几个词 |
| `parse.fieldSep / senseSep` | `auto` / `；;／/|` | 规则解析的分隔符 |
| `memorize.position/offsetY` | `centerTop` / 0.3 | 记忆题干出现在原落点还是居中偏上 |
| 优先度 | `balanced` | 见 §3.7 |
| `learnPick.samePriorityOrder` | `createdAt` | 同级内是「先录入先背」还是确定性随机 |
| AI 四项 | 空 | 地址 / 模型 / 密钥 / 是否强制走代理 |
| `practice.autoSpeak / speakRate / hintFails` | `true` / 1 / `false` | 朗读与提示判分 |
| `speech.*` | 浏览器语音 | TTS 供应商 / 音色 / 语速 / 有道密钥 / 口音 / 变体 |
| `backup.remindOnClose` | `true` | 关页前提醒导出 |
| `cloud.*` | 关闭 | 后端地址 / 同步码 / 自动同步 / 两个游标 |

> **术语｜`reviewPriority`（属性⑥）与 `word.priority` 是两回事**：前者是**算出来的实数**，决定「复习先抽谁」；后者是**用户手设的 1~5**，决定「背诵先抽谁」。两者唯一的关系是「复习优先度公式里可以引用失败率等属性」。

### 3.10 键盘与语音【代码】

- 白纸流程**只有一个** window 级 `keydown`：焦点在 `INPUT/TEXTAREA/SELECT/BUTTON` 上时**完全让给原生**；答案卡打开时 `Enter/空格` = 推进；否则只认 `Enter`（浏览态 = 再背一个；作答态 = 提交）；有 modal 时不抢键；
- 桌面按钮文案直接印 `再背一个 (Enter)`；手机上是**圆形按钮 + 圆内 2~3 字 + 圆下小字**（「完/存/忆/背/复/重」），状态以原按钮为唯一来源，避免「圆里一个字、其实是另一件事」；
- **TTS 出现的位置**：① 单词上纸时自动朗读（`autoSpeak` 默认开）② 记忆环节每题开头再读一遍 ③ 考核中「🔊 朗诵一遍」提示 ④ 单词卡上的 🔊；iOS 首次必须**手势解锁**（`SpeechGate` 挂一层「点击屏幕开始」，点击时**同步**发一次静音朗读）。

### 4.1 二期怎么用（一句话）

**跟 AI 说「我在定语从句这块不行」→ AI 拆成若干张结构化卡片 → 逐张预览/采纳 → 入库 → 逐张自评学习 → 让 AI 出题考你、AI 按标准打分 → 掌握度低了自动排到前面复习；复习中途还会跳去一期背 5 个单词。**

### 4.2 聊天式录入【代码】

- 入口 `#/kc/import`：输入框 Enter 发送 → 取会话历史（**按条数 6 条 + 字符预算 4000 双重截断，按码点计数**，最近一轮必留）→ `analyzeWeakPoint()` → 渲染若干张**卡片预览**；

- 面板里的会话与卡片状态**不落库、刷新即清**；
- 已有标题会**滤掉墓碑后**喂给 AI，让它说清楚「哪些是新的、哪些和已有重合」；
- 兜底：可以手动新建一张空白卡（`未命名知识点`）。

**AI 输出的 JSON 契约**（提示词里写死）：

```json
{ "cards": [ { "title": "…", "summary": "…",
               "blocks": [ … ], "examTags": ["fill","sentence"],
               "examLoad": { "types": [...], "estMinutes": 4 } } ] }
```

提示词规则包括：自动拆成 2~5 个知识点、每卡 2~4 个块、每块一句话、**优先用二分对照表述**、表格 `rows` **全是数据行（不写表头）**、例句最多 1~2 个并配翻译、**不写 HTML/markdown**。

### 4.3 卡片的数据结构：块（Block）【代码】

一张卡片 = 标题 + 摘要 + **块数组**（结构自由靠任意组合）+ 考法标签 + 出题量 + 来源 + 属性。块共 **8 种**：

| type | 用途 | 专属字段 |
|---|---|---|
| `heading` | 小标题 | `content` |
| `text` | 正文段落 | `content`（多行用 CSS `pre-wrap`，**不是**把 `\n` 换成 `<br>`） |
| `example` | 例句 | `content` + `translation` + `note` |
| `list` | 列表 | `items[]` |
| `table` | 表格 | `rows[][]`（**全是数据行，无表头**） |
| `code` | 代码块 | `content` + `lang`（**只作 CSS class，过安全字符集**） |
| `quote` | 引用 | `content` |
| `tip` | 提示/易错点 | `content` |

> **术语｜XSS（跨站脚本注入）**：把 `<script>` 或 `<img onerror=…>` 之类塞进页面执行。二期内容**全部来自 AI 与用户粘贴**，属于不可信输入。本项目的防线是**只走 `textContent` / `createTextNode`**（`core/blockRender.ts` 的 `el()` 是唯一入口），`<script>alert(1)</script>` 只会原样显示成一行字；未知块类型降级为纯文本，单块渲染失败被 try/catch 兜住。自检里有专门的 XSS 组。

### 4.4 学习流程（KcStudyPage）【代码】

`阶段机：picking → cards → finished`

1. **选数量**（1~50，可看「未学/学习中」的存量）；
2. **逐张展示卡片**：标题 + 右上角考法标签 chip + 摘要 + 可滚动的块内容；底部三档自评「不会(1) / 模糊(2) / 会了(3)」+ 「斩」；键盘 `1/2/3` 自评、`Esc` 保存并退出；
3. **学习流程不做「掌握判定」——完全由自评承担**。每次自评：写 `lastSelfScore` 与 `learnedAt`（首次）→ `updateAttrs` 内部**重算 `mastery` 与 `reviewPriority`** → 首次自评把状态从 `unlearned` 推到 `learning` → 每一步都写会话（断电不丢）；
4. 全部过完 → 三个出口：`开始做题` / `先不做` / `再学一轮`；做题跳 `#/kc/exam`（出题完成后卡片状态变 `learned`）。

### 4.5 出题与评分（KcExamPage）【代码】

**题型**（`EXAM_TYPES`，新增题型只改这个数组，任何地方都不许写死「4 种题型」）：`fill 语法填空`、`sentence 独立写句子`、`choice 选择题`、`judge 判断正误`。

**出题材料**每轮只读一次，三样东西：

1. **每日语境词**（`dailyContextWords`）：每天 5 个互不相关的英文实词，只有 `confirmed === true` 才参与出题；AI 每道题挑最贴切的一个写进 `contextWord`，并且解析层会**把它约束回今日词表**（不在表内就留空）；
2. **近 3 天的题干**（`examDedupeLookbackDays = 3`）——用于**防重复出题**；
3. **题库样题**（`bankQuestions`，用户导入的真题/参考题）：按题型洗牌抽 3~5 条当**风格示例**（模仿排版，不照抄）。

**题目生成**：先按「卡片 × 题型」占位（每种卡片最多 3 道，题型取 `examLoad.types` → 退回 `examTags` → 兜底 `['fill']`），再用自研 `withConcurrency(…, 3)` **一口气把整轮题出完**；**单题失败只写进自己的 `slot.error`，不阻断其余题**（失败可通过「重试」单独重发）。

**JSON 契约与清洗**：出题 `{question, contextWord, expected}`、评分 `{score, reason}`、语境词 `{words:[…5]}`。解析层与录入**同一套三级降级**，并且 `score` **钳到 1~3 整数**（容忍 `"2分"` 这种字符串）、`estMinutes` 钳到设置区间。

**答题 → 评分**：状态机 `preparing → answering → grading → graded → … → done`（另有 `error`）。四种题型各有作答控件（`choice` 从题干抽 `A-D` 行渲染按钮，抽不到退化成输入框；`judge` 给对/错；`fill` 单行；`sentence` 多行）。评分**不是本地义项匹配**，而是**把答案交给 AI 按 rubric 打分**：

| 题型 | 3 分 | 2 分 | 1 分 |
|---|---|---|---|
| `fill` | 完全正确 | 词根对、形式错 | 错或空 |
| `choice` | 选对 | — | 选错 |
| `judge` | 判断对且理由对 | 判断对、理由错 | 判断错 |
| `sentence` | 语法对 + 用对目标结构 + 语义通顺（三项全中） | 两项 | 其余 |

**评分失败不阻断**：给默认 2 分 + 提示手动改；评分卡**永远保留手动改分**入口（改分同时更新题目历史里的分数与卡片的 `lastExamScore`）。T3 的「提示后算未通过」在这里落地为**把 AI 给的分数压到 1 并改理由**，保证这件事能传到掌握度。

> **术语｜rubric（评分量规）**：写给评分模型的「评分标准表」，把 1/2/3 分各自的判据说清楚。目的不是让 AI 更聪明，而是让**不同次评分之间可比**。
> **术语｜JSON 契约**：提示词里明确规定「你必须输出这个形状的 JSON」，代码再按这个形状解析 + 清洗。AI 不保证守约，所以解析层必须有降级策略（见 §6.1）。

### 4.6 复习流程与「桥接」（一二期唯一的连接点）【代码】

四个阶段由 `KcSession.stage` 串起来，**每一步都能「保存并退出」，重进按 stage 回到对应环节**：

```
cards（逐张看卡片、自评、可斩）
  → words（★桥接：跳去一期白纸背 5 个单词）
  → exam（AI 出题 → 作答 → 评分）
  → done（收尾：写回 lastReviewAt / reviewCount / 掌握度 / 优先度）
```

- 复习抽卡：`learning | learned` 的卡片按 `reviewPriority` **降序**，同分看 `lastReviewAt` 更早；
- **桥接**（`KcWordBridge`）的三条纪律（代码注释）：**复用一期页面（不复制代码）、不改一期核心逻辑（只在外层调用）、用一期自己的 `sessions` 表存桥接会话**（与二期 `kcSessions` 分开，互不覆盖）；
- 词源优先级：一期**未背过的新词**（按录入时间升序）→ 没有新词则退化为**按一期复习优先度降序的旧词** → 词库为空则**跳过这一步**；上限 `reviewWordLimit = 5`；横幅会说明「这些词是新词还是旧词」并提供「跳过」；
- 退出桥接时清掉一期会话，避免一期「背诵」页误以为有未完成的复习；
- 复习结束显示小结：平均掌握度 + 「需要重点回顾」条数（`mastery < 0.34`）。

### 4.7 掌握度公式：二期的算法核心【代码】

```
selfNorm = 自评 / 3          examNorm = 考核 / 3
dir      = selfNorm >= examNorm ? asymmetry : 1 / asymmetry
mastery  = w1*selfNorm + w2*examNorm − penalty * dir * |selfNorm − examNorm|
           → 钳到 [0,1] → 保留 3 位小数
```

默认参数：`w1 = 0.6`（自评权重更高，因为主观题 AI 评分只能算参考）、`w2 = 0.4`、`penalty = 0.8`、`asymmetry = 2`。只有一边有分时，缺的一边用**中性先验 0.5**（= 3 分制里的「模糊」）补齐。

**为什么要加方向系数 `asymmetry`**（这是代码里注释比实现长的地方）：主提示词给的对称惩罚在 `0.6 > 0.4` 的权重下会算出**「盲目自信(自评3/考核1) = 0.2」高于「低估自己(1/3) = 0.067」**，与「盲目自信最危险」的结论正好相反。加了方向系数后（`a ≥ 1.3` 起成立，取 2 让四个关键格落在 1 / 0.333 / 0.667 / 0）：

| 自评＼考核 | 未考 | 1 不会 | 2 模糊 | 3 会了 |
|---|---|---|---|---|
| 未自评 | 0 | 0.167 | 0.5 | 0.5 |
| 1 不会 | 0.333 | 0.333 | 0.333 | 0.333 |
| 2 模糊 | 0.333 | **0** | 0.667 | 0.667 |
| 3 会了 | **0** | **0** | 0.333 | **1** |

两个「故意的 0」：`3/1`（说自己会、一考不会 = 最危险，视作没学过要重来）与 `2/1`。而 `1/3`（低估自己但真会）只到 0.333，不会被惩罚到底。**只有 `3/3` 才是 1.0**；「自评 3、还没考」= 0（光自己说会了不算掌握）。

**复习优先度**（二期）同样是「表达式优先、固定公式兜底」两条路：

- 表达式模式（三预设）：`balanced = daysSinceReview*0.5 + (1-mastery)*10`、`weakFirst = (1-mastery)*20 − reviewCount`、`forgetting = daysSinceReview/(reviewCount+1) + (1-mastery)*8`；
- 兜底固定公式：`(1 − mastery) * masteryWeight + daysSinceReview * staleWeight + gap * gapWeight`（默认 `1 / 0.02 / 0.5`）；
- 其中 `gap`（自评与考核的归一化差距）单边时**打折 0.5**——「还没考过」不等于「考砸了」；
- `isBlindSpot()`：`自评 − 考核 ≥ 0.34` 就打 ⚠️ 标记（识别盲目自信）。

**改参数后必须「重算全部」**：库里存的 `attrs.mastery` 是旧公式算的，所以设置页每次写完设置都会逐张重算并写回，且用 `1e-9` 容差**只写真的变了的卡**（避免无意义的 `updatedAt` 刷新引发同步推送）。

> **术语｜IndexedDB / object store / index**：浏览器内置的结构化事务型数据库；object store 相当于「表」，index 是给某字段建的可查询结构。**踩过的坑**：缺该字段的老记录**不会被该字段的索引覆盖**，所以补数据的迁移只能用 `getAll()` 全读，不能用索引开游标。

**版本迁移史**（每一段都**幂等**，因为自愈修复会用 `DB_VERSION + 1` **重跑同一段代码**）：

| 版本 | 内容 |
|---|---|
| v2 | 给 `words/sources` 补云同步要用的 `updatedAt`（老数据用 `createdAt` 兜底） |
| v3 | 新增二期四张表（**纯加法，一期数据一条不动**） |
| v4 | 新增二期会话表 `kcSessions` |
| v5 | **不是新功能，是修复**：有些库版本号已是 4 但表没建出来，而「版本号相同就永远不会再触发 `onupgradeneeded`」→ 只能**抬版本号**逼一次重跑建表 |
| v6 | R1：给老词补 `priority = 3`，并**刷新 `updatedAt`**（不刷的话别的设备拉到的还是缺字段的旧版本） |
| v7 | T2：给老词补 `attrs.examCount = failCountTotal × 2` |

**★ v6/v7 暴露的一个真 bug 与它的修法**：原来每段迁移各自 `getAll()` + 各自 `put()`。同一事务里注册多个 `getAll()` 回调会拿到**两份独立快照**，后跑的那段会用「原始行 + 自己的补丁」覆盖前一段刚写进去的字段——实测把刚补好的 `priority` 当场抹掉。现在改成 **`migrateWordRows()`：读一次 → 每个迁移改**同一个行对象** → 只写一次**（`dbSchema.ts:127-142`）。

**「One of the specified object stores was not found」三级自愈**（用户实测报错，两轮才查透）：

1. `withStore()` 发现连接里缺这张表 → 释放连接、重连；
2. 仍缺 → `repairUpgrade()` 以 `DB_VERSION + 1` 开库**强制重跑建表**；
3. 仍缺 → 抛 `StaleDbError`；外层 `withDbRetry` 默认再修一次。
   配套修复：`tx()` 把 `db.transaction()` 包进 try（它在 Promise 构造器里抛出**不会被 reject 接住**，会变成未捕获异常把整页变「页面渲染失败」）；收到别的标签页的升级通知时除 `close()` 还要**清掉连接缓存**（不清就会继续用已关闭的连接——这正是那个报错的根因）。

### 5.2 云端：Turso（libSQL / SQLite）【代码】

> **术语｜Turso / libSQL**：SQLite 的云托管版本与它的 wire 协议实现，通过 `@libsql/client` 用 HTTP 访问，免费额度足够个人自用，**不需要自己运维数据库**。本地开发可以把地址指向 `file:./.tmp/dev.db`，跑的是**和线上完全同一套 SQL**。

| 表 | 关键列 | 归属 |
|---|---|---|
| `words` | `id, space_key, en, phonetic, example, senses(JSON), source_id, raw_sources(JSON), attrs(JSON), status, priority, learn_order, created_at, updated_at, deleted` | 一期 |
| `sources` | `id, space_key, name, priority(废弃), created_at, updated_at, deleted` | 一期 |
| `knowledge_cards` | `id, space_key, title, summary, blocks(JSON), exam_tags(JSON), exam_load(JSON), source(JSON), attrs(JSON), status, created_at, updated_at, deleted` | 二期 |
| `daily_context_words` | `id, space_key, date, words(JSON), source, confirmed, created_at, updated_at, deleted` | 二期 |
| `exam_records` | `id, space_key, card_id, date, type, question, user_answer, ai_score, ai_reason, context_word, created_at, updated_at, deleted` | 二期 |
| `bank_questions` | `id, space_key, type, content, source, created_at, updated_at, deleted` | 二期 |

**两个关键设计**：

1. **主键必须是复合的 `PRIMARY KEY (space_key, id)`，不能只用 `id`**。同步是「客户端生成 uuid → 上传」，两台设备或两个空间完全可能撞同一个 id；若主键只有 id，`ON CONFLICT(id) DO UPDATE` 会把 `space_key` 一起改掉 → **一个空间的数据覆盖另一个空间**，隔离直接失效。老库检测到旧主键会**重建表搬数据**（同一 `(space_key,id)` 只保留 `MAX(rowid)`）。
2. **没有 users 表，没有任何存密钥的表**——这是「服务器不接触 AI 密钥」的结构性保证。
   老库补列也是幂等的：`words.priority`、二期三张小表的 `updated_at/deleted`，都先查 `PRAGMA table_info` 再 `ALTER TABLE`。`sources.priority` 因为**是 NOT NULL 且无默认值**（SQLite 改不了已有列默认值），只能「建新表 → 搬数据 → 换名」。

> **术语｜空间（space）与 `space_key`**：本项目**没有注册流程、没有 spaces 表**。空间的全部含义就是「行上的一列 `space_key`」——一个 64 位十六进制字符串。首次 push 就是注册；未注册的空间 pull 回来一个空数组。**任何人只要知道明文同步码，就等价于拥有这个空间**（见 §5.5 安全分析）。

### 5.3 云同步协议【代码】

**一次 `syncOnce()` 固定「先拉后推」**：

```
① pull(since = lastSyncAt)          拿云端增量（★包含 deleted=1 的墓碑）
     ├─ 云端 updatedAt >  本地 → 用云端覆盖本地（后写覆盖）
     ├─ 云端是墓碑            → 本地按规则处理（一期真删 / 二期留墓碑）
     └─ 本地更新或本地独有     → 留着，等第 ② 步推上去
② push(本地所有 updatedAt 在游标之后的行)   每批 ≤ 500，自动分批
     └─ 服务端按后写覆盖处理，返回 { applied, conflicts, skipped, serverTime }
③ 更新两个游标
     ├─ lastSyncAt  = serverTime（界面显示用）
     └─ lastPushAt  = 本次真正推到的最大 updatedAt（下次推送起点）
```

**为什么必须先拉后推**：不先拉就推，会把本机较旧的版本推上去白跑一次（服务端会按 `updatedAt` 更旧而拒绝）。

**★ 分批推送里的两个坑**（`pushAll()` 注释里是完整推导）：

1. **同毫秒批量写入**：导入/粘贴/批量改属性会给几百条记录**完全相同的 `updatedAt``。若用「`updatedAt > 游标`」分页：游标停在 `max` → 下一轮把同批剩下的**全漏掉**（实测 1100 条只推上去 500 条）；游标 +1 → 又把同批剩下的**全跳过**。
   **正确做法**：`listDirty*(since)` 用 **`>=`** 返回**候选集**，再用 `pushedIds` 集合排除本次已推的；游标只推进到「本页待推数据的真实最大 `updatedAt`」。
2. **`hasMore` 时不要推进 `lastPushAt` 到 `serverTime`**，否则本地没拉到的行会被误判成已在服务端、永远不再推。

**冲突策略：后写覆盖（Last-Write-Wins）**，按 `updatedAt` 比大小，**相等时进者赢**：

- 服务端：`incoming.updatedAt >= server.updatedAt` 才写，更旧的计入 `conflicts` 且不覆盖；
- 客户端：`local.updatedAt >= remote.updatedAt` 就跳过（本地改动还没推上去时不能被旧云端覆盖）；
- 三个计数：`applied`（真正 upsert 的行数，**重复推同样内容也算**）、`conflicts`（被挡下的行数）、`skipped`（结构不合法被跳过的行数，**脏数据不整批失败、只跳过并计数**）。

> **术语｜Last-Write-Wins（后写覆盖）**：冲突时不问用户，直接取「版本号更大」的那个。优点是实现简单、无需人工介入；代价是**两台设备离线各改同一个词，后同步的会覆盖前面的**（本项目在「已知限制」里明确承认）。

**删除语义（最容易搞混，单独列表）**

| 场景 | 行为 |
|---|---|
| 用户「斩」词（背诵页/列表页） | **软删**：`status='chopped'`（不是墓碑） |
| 用户「删除」词 | **硬删**（本地直接移除） |
| 删除来源 | **软删**：写 `deleted=1` 墓碑（否则别的设备会复活它） |
| 云端下发 `deleted=1`（一期） | **本地真的删掉那一行**（墓碑只用于传输） |
| 二期「斩」卡片 | **软删**：`deleted=1` + `status='chopped'`，**本地保留墓碑** |
| 云端下发 `deleted=1`（二期） | **本地落成墓碑**（不真删），这样「已斩」列表能看到、能复活 |
| 清空云端（purge） | **真 DELETE**，只删当前 `space_key`，需带 `{confirm:"DELETE"}` |

> **术语｜墓碑（tombstone / soft delete）**：删除时**不真删**，而是留一条「这行已删除」的记录让别的设备也能知道。不留墓碑的话「A 设备删了、B 设备还留着」会在下次同步被 B 复活。**本项目的已知限制：墓碑不会自动清理**（`HANDOVER` 把「清理 30 天前的墓碑」列为待办）。

**调度与失败处理**：

- 数据变动 → `emitDataChanged()` → `scheduleSync()` **防抖 5 秒**（把连续操作合并成一次）；启动时也同步一次；设置页有「立即同步」（无视 `autoSync` 开关）；
- 单请求超时 15s；失败只对 `408/425/429/500/502/503/504` **重试一次**、间隔 2s；
- 同步失败后 **60 秒退避重试**；**不并发**（正在跑时只置 `pendingAgain`，跑完补一次）；**连续失败 3 次**才把轻提示转成常驻提示；失败原因写进 `settings.cloud.lastError`（只给界面显示，**不含密钥**）；
- **一期与二期各持有一个调度器实例**、各有独立游标（`settings.cloud` 与 `settings.kc.cloud`），二期后端抽风不会把一期也拖进「连续失败 3 次」。

> **术语｜防抖（debounce）与退避（backoff）**：防抖 = 事件连续发生时只在停止后执行一次；退避 = 失败后等一段（越来越长）时间再试，避免对故障中的服务反复冲击。

### 5.4 认证与安全模型【代码】

**同步码 → spaceKey**：

1. 用户**自己编**一个码（≥ 8 位、必须同时含字母和数字）；
2. 明文只存在**这台设备的浏览器**里（IndexedDB + localStorage 镜像）；
3. 发请求前做 `sha256(码.trim())` → 64 位小写十六进制；
4. 所有同步请求带请求头 `X-Space-Key: <哈希>`；
5. 服务端只接受 `/^[0-9a-f]{64}$/i`，否则 **401**；日志只打前 8 位缩写。

> **术语｜SHA-256**：单向哈希函数，把任意输入变成 64 位十六进制、**不能反推原文**。本项目用它把同步码变成「凭据」，好处是服务器日志/数据库里都看不到明文。

**空间隔离纪律**：**每条 SQL 都必须带 `WHERE space_key = ?`，且 SQL 只能出现在 `api/_lib/*Inventory.ts`**。一期与二期都有行为级隔离测试（同一 id 在两个空间各存一份、改 A 不动 B），二期另有**源码级护栏**逐条扫描模板字符串；一期目前只有注释级纪律（见 §8 风险）。

**方案 B：服务器永不接触 AI 密钥**（铁律 R4）具体怎么落实：

- 密钥只存浏览器（`settings.ai.key`），随**每次请求**的 `Authorization` 头进代理、**用完即弃**；
- `/api/ai-proxy` 的文件头写着四条「不写库 / 不写日志 / 不缓存 / 不回显请求头」，其 import 列表里**没有** `_lib/db`——这条有测试守着；
- 请求体原样转发；日志只打「一行计数 + 上游状态」，**不打词条内容、不打密钥**；
- 响应带 `Cache-Control: no-store`、剥掉 `set-cookie`；
- **防滥用两道闸**：① 来源白名单 `ALLOWED_ORIGIN`（**明确要求不要用 `*`**）② 上游主机白名单 `AI_ALLOWED_HOSTS`（防 **SSRF**，只允许 https，白名单内的主机才允许 http——那是为了本地假上游测试）。
- **`/api/tts-proxy` 更严**：上游地址受限于 `TTS_TARGET`、**不接受客户端指定目标**，并且**不转发 `Authorization`**。

> **术语｜CORS（跨域资源共享）**：浏览器的同源策略默认禁止网页请求别的域；上游 AI 服务普遍不返回 CORS 头，所以浏览器直连会被拦——这正是本项目需要「代理」这个角色的根本原因。本项目服务端会**回显请求的 Origin**（而不是 `*`）并自己回答 OPTIONS 预检，且在来源不被允许时**也回 CORS 头**，这样前端能看见「来源被拒」而不是一句含糊的跨域错误。
> **术语｜SSRF（服务端请求伪造）**：攻击者让你的服务器当跳板去请求任意地址。防法是**上游主机白名单**。
> **术语｜令牌 vs 口令**：本项目没有任何「密码」；同步码本质是一个**共享口令**，不是账号体系（无找回、无注销、泄露即等于空间泄露）。

### 5.5 备份 / 导出 / 本地文件夹【代码】

- **导出的 JSON 结构**：`{ version: 1, exportedAt, words[], sources[], settings }`，文件名 `白纸单词备份_YYYYMMDD_HHmm.json`；
- **恢复两种模式**：`merge`（按 `英文小写::sourceId` 判重，跳过已存在）与 `replace`（先清空 words+sources 再全量写入，需二次确认）；
- **本地文件夹自动备份**：用 File System Access API 把**同一份序列化结果**写进用户选定的文件夹（防抖 2 秒、句柄存 settings 表）；只有 Chrome/Edge 支持，Safari 降级为手动导出（浏览器重启后需要用户点一下恢复权限，顶栏有黄条）；
- **关页提醒**：距上次手动导出超过 7 天且已连接本地文件夹时，关页前弹浏览器原生提醒。

> ⚠️ **【代码·安全发现】导出的备份 JSON 里含明文密钥**：`buildBackupFile()` 直接整份塞入 `Settings`，其中包含 `settings.ai.key` 与 `settings.speech.youdao.appSecret`，序列化前**没有任何剥离/脱敏**；本地文件夹自动备份走同一条路径。这与 `HANDOVER.md` 自述的「导出备份**不包含**密钥」**直接冲突**。注意它**不违反 R4**（密钥从未上传服务器），风险面是「用户把备份 json 交给别人 / 传到网盘 / 提交到仓库」。修法很局部：导出前把这两处置空（是否要保留「导出含密钥的完整备份」选项由作者决定）。

### 5.6 PWA 与离线【代码】

- `public/sw.js` 是**手写的 194 行 Service Worker**（不用 Workbox）：
  - **安装**：先 `fetch('./index.html', {cache:'no-store'})`，再用正则从 HTML 里**抠出所有同源资源**逐个预缓存（另补图标与 manifest）；单个失败不影响整体安装；**不预缓存**预设词表（442 KB，改成首次点击时按 Cache First 落缓存）；
  - **激活**：删掉旧前缀的缓存 + `clients.claim()`；
  - **更新**：新版本进 waiting **不自动刷新**（会打断正在背单词），由页面提示，用户点刷新时才 `skipWaiting()`；
  - **取数**：`mode==='navigate'` → **Network First**（断网回落缓存的 index.html）；带后缀的同源静态资源 → **Cache First**；**跨域一律不碰、`/api/` 一律不缓存**。
- **离线可用范围**：背单词 / 复习 / 列表 / 统计**完全可用**（数据在 IndexedDB）；云同步、AI 解析、TTS 离线不可用但**不阻断**（符合本地优先纪律）。
- **小瑕疵**【未确认是否有意】：预缓存清单里写了根路径 `favicon.png`，但 `public/` 下只有 `icons/favicon.png`，那条 404 被 `if (r.ok)` 吞掉。

> **术语｜Service Worker**：浏览器里的后台脚本，能拦截页面的网络请求，决定「走缓存还是走网络」——离线的关键。
> **术语｜Cache First / Network First**：前者优先用缓存（静态资源，快）；后者优先走网络、失败才回落缓存（页面导航，保证内容新）。

## 6. 横切机制

### 6.1 AI 调用链与提示词工程【代码】

> **术语｜数据流**：用户浏览器 → 直接调 AI 服务（**首选**）；若被 CORS 拦 → 改走 `/api/ai-proxy` 转发一次。

**两条路径 + 自动降级**：

- **直连**：`POST <用户填的地址>`，头只有 `Content-Type` + `Authorization: Bearer <密钥>`；
- **代理**：`POST <后端地址>/api/ai-proxy`，头多一个 `X-Target-Url`（目标 AI 的完整地址）；
- 策略：设置了「强制走代理」就直接走代理；否则**先直连**，捕获异常后按 `isNetworkLikeError()` 分类——**超时与明确的 HTTP 错误不重试**，只有**网络层失败**（浏览器把 CORS 报成 `TypeError: Failed to fetch`）且配了后端地址时才**自动切代理一次**；
- 实际走的路径记在模块级变量，设置页会显示「上次调用走的是：直连 / 代理」——这是一个很实用的可观测性设计。

**请求/响应契约**：请求体 `{ model, messages, stream: false }`，`jsonMode` 时加 `response_format: {type:'json_object'}`；响应只取 `choices[0].message.content`。客户端**恒 `stream:false`**（所以代理虽然具备 **SSE** 流式透传能力，目前只是能力储备）。

**三层重试与错误分类**：

1. `response_format` 被 400/422/500 拒绝 → **去掉它重试一次**（不是所有模型都支持 JSON 模式）；
2. 直连失败 → 切代理一次；
3. 批次级不重试，失败写进 `job.errors`，界面提供「重试失败批次」。

错误文案是**给人看的**：401/403「密钥无效或未填写」、404「模型名或接口地址不对」、429「触发限流，请稍后重试」、≥500「服务端错误」、超时「请检查网络或换一个接口地址」、连不上「去设置页开启『走无状态代理』」。

**提示词工程与规则固化**（这是本项目最有意思的工程实践之一）：

- `AI_RULES.md` 第 4 节规定了两段**必须逐字出现**在提示词模板里的文字（4.1 义项处理规则、4.2 禁止时间限制）；它们的**唯一副本**在 `src/services/promptRules.ts`，被录入、重整理、二期录入、二期出题四处**直接插值**而不是各自重写；
- 校验分两级：`scripts/checkRules.mjs` 只做「指纹字符串是否出现」；更强的**逐字比对**在 `npm run test:r4`——它从 `AI_RULES.md` 抠出 4.1/4.2 的代码块**原文**，断言常量与原文 `===`，再断言各提示词里 `includes()` 它。**手打漂移（全角引号、末尾空格）会被抓红**；
- **义项规则（R2）的唯一权威**是 `src/core/senseRules.ts`，硬约束执行点是 `normalizeAliases()`（把「跑步，奔跑」这种**打包项**拆开）与 `validateSenseShape()`；所有非 AI 的写入路径（合并页、卡片编辑、预设导入）都经过 `createSense()`，在这一层兜住。自检里有「**证明旧写法确实会判错**」的回归防线。

> **术语｜提示词工程（Prompt Engineering）**：把「希望模型做什么」写成文字指令。本项目的教训是：**提示词与代码一样会漂移**，所以要把关键条款固化成常量并让测试逐字校验。
> **术语｜降级（fallback）**：主路径失败时走备用路径。本项目在解析层有「三级降级」、在 AI 路由上有「直连→代理」、在 TTS 上有「缓存→第三方→浏览器语音」。

**AI 输出的三层清洗**（以录入为例）：`stripCodeFence()` 去掉 ``` 包裹 → `extractFirstJsonObject()` **括号计数 + 字符串/转义感知**地抠出第一个 JSON 对象（避免 `lastIndexOf('}')` 把后面的解释文字也圈进来）→ 三级降级解析 → 逐字段钳制（卡片数 ≤ 12、每卡块数 ≤ 40、`estMinutes` 钳到设置区间、题型走白名单、文本 `sanitizeText` 去控制字符并限长）。

### 6.2 TTS 抽象层【代码】

- **统一入口** `speak()/speakAsync()`，三级调度：1.5 秒内重复触发去重 → 第三方 + 缓存 → 浏览器语音（**永不抛错**）；
- **provider 抽象**只负责「文本 → 音频字节」，播放与缓存统一在外层做；
- **浏览器语音**（默认、免费、离线）：按 `localService` + premium/enhanced/siri 质量标记**打分挑语音**（不依赖 `getVoices()` 顺序），存的是**名字**而不是索引/对象（不同设备可用语音完全不同，名字对不上时自动回退）；
- **有道 TTS**：返回 mp3 字节、需联网、**按字符计费**、可缓存，走 `/api/tts-proxy`；
  - **签名在浏览器端算**：`salt = randomUUID()` → 截断输入规则 → `SHA256(appKey + input + salt + curtime + appSecret)`；三个坑写在文件头（拼接用 **q 原文**、长度是**字符数**、签名前**不做 URL encode**）；
  - **双实现对拍**：Node 参考实现 `scripts/youdaoSign.mjs` 与浏览器 `__selftest.youdaoSign`，真浏览器测试断言两者 sign **完全一致**；
- **缓存**：key = `SHA-256(providerId + voice + speed + variant + text)` 取前 32 位；落在 IndexedDB `ttsCache`，**不设过期**（合成结果确定性）；
- **计费与限流保护**：缓存命中秒播、不发请求；1.5 秒去重；**连续失败 3 次熔断本会话**（改密钥或测试成功即复位）；失败**静默降级**不弹框；`q > 2048` 直接拒；速率钳到 0.5~1.5；
- **文本预处理 `normalize()`**：剥离音标与中英括号内容、英文模式下删中文与全角标点、展开 33 项缩写（`don't → do not`）、连字符转空格、数字转英文（`1999 → nineteen ninety nine`）。

> ⚠️ **【代码·未接线】`speech.variant`（"single" | "normal+slow"）当前不生效**：类型与设置页都有这一项，文档也写了「该模式每词合成两遍（1.0 与 0.8），朗读时交替使用」，但调度层**写死 `variant: 0`**（`src/services/tts/index.ts:285,293`），`youdao.synth` 也只用 `speed`。结果：**该选项不产生任何慢速音频**。【未确认】是否属于有意搁置。

### 6.3 文件解析与预设词库【代码】

- **格式**：`.txt/.csv/.md/.tsv` 按纯文本、`.docx`（mammoth，动态 import）、`.pdf`（pdfjs-dist，动态 import + 真 worker URL；`NO_TEXT_LAYER_THRESHOLD`/`SCANNED_AVG_THRESHOLD` 判定扫描件并**明确报错**）；`.doc` 拒绝；按**扩展名**而不是 MIME 判定（docx 的 MIME 五花八门）；
- **编码**：UTF-8 优先，出现替换字符时与 GBK/GB18030 比替换字符数取少者；
- **文本归一化**：统一 LF、去行尾空白、3 个以上空行压成 1 个——**不删空行**（AI 靠它分辨词组边界）；
- 解析结果直接写进**同一个 textarea**（唯一事实来源），因此「上传文件」与「手打文本」完全等价，不产生第二条解析分支；
- **断点续传**：录入任务每批 `saveJob()` 落 **sessionStorage**，刷新不丢；提供「继续解析 / 重试失败批次 / 放弃并清空」；
- **重新分析义项（reparse）**：范围可选「某来源 / 全部未整理过 / 全部词」；分批 50、批间 500ms、每批最多 2 次尝试、单批失败只记录并继续、**AI 漏掉的词保留原样**、可中断；user message **刻意只发** en/phonetic/example/senses，避免 AI 顺手改 priority/status/attrs；写库只替换 `senses/phonetic/example`；结果以 **diff** 展示（默认全选、旧行灰、新行高亮、音标例句只补不覆盖）。

**预设词库构建**：`一期预设词库/*.txt`（原始素材）→ `scripts/preset-lib.mjs` 解析 → `scripts/build-presets.mjs` 输出 `public/presets/*.json` **和** `src/core/presets.ts`（清单）。

- 词条 JSON 用**数组**而不是对象（省约 40% 体积）：`["abandon", ["v. 放弃；抛弃"], "əˈbændən"]`；
- **档位之间递归剔除**：每档减掉所有更低档的产物，保证**任意两档不相交**，构建脚本会断言这个不变量，不满足直接 `exit(1)`；实测 初中 1987 / 四级 3104 / 六级 2060 / 考研 295（因 94.2% 与低档重叠只剩这么多）/ 雅思 904；
- `--check` 只校验不写文件，被 `test:presets` 调用。

## 7. 架构与交互的「为什么」（设计取舍复盘）

| 设计 | 换来什么 | 代价 / 风险 |
|---|---|---|
| 无前端框架 + 手写 `h()` | 零依赖、包小、行为完全可控 | 没有响应式，数据变了必须显式重画；踩过「往已脱离文档的旧节点里画」的 bug |
| 本地优先 + IndexedDB | 打开即用、断网可用、无服务器成本 | 多设备一致性只能靠「后写覆盖」，冲突无法自动合并 |
| 用「同步码」而不是账号 | 零注册、零运维、服务器不知道明文 | **口令即全部权限**：泄露 = 空间泄露；无找回/注销；弱口令可被暴力猜（见 §8） |
| 服务器不接触 AI 密钥（方案 B） | 无密钥托管风险、无托管成本 | 用户要自己填四五个字段；CORS 需要一层代理 |
| 优先级「绝对优先」 | 行为可预测、可复核（连续抽 10 次前 5 次必是 P5） | 低优先级词可能长期不被抽到 |
| 复习不选数量、点一下加一个 | 不需要猜数字，节奏自己控 | 与「间隔重复算法（SM-2/FSRS）」不同：**本项目不做固定间隔排程**，只做「优先度排序」 |
| 二期完全独立于一期 | 互不拖累、可分别上线 | 两套相似代码；`activeExpr` 与 `activeKcExpr` 行为不一致 |
| 判分「代表义项 + 近义词命中即通过」 | 纯本地、无需 AI、可离线、判定可解释 | 依赖录入时的义项质量；**打包义项会直接判错**（因此有 81 项回归测试守着） |
| 反 AI 输出的 XSS 靠「只用 textContent」 | 结构性免疫，而不是「过滤黑名单」 | 需要所有渲染路径都遵守（本项目把唯一入口收在 `blockRender.el()`） |

> **术语｜间隔重复（Spaced Repetition）/ SM-2 / FSRS**：按「快要忘记的时刻」安排复习的算法族。**本项目没有采用**，而是让用户用表达式自定义优先度（可调时间、失败率、是否需拼写等信号），属于「可解释的优先度排序」而不是「固定间隔排程」——这是本报告认为最值得注意的产品差异点。

## 8. 观察、风险与改进建议

按严重度分级。前三条是**需要作者决定的真问题**，其余是技术债与文档漂移。

### 8.1 值得优先处理

**① 导出的备份 JSON 含明文 AI 密钥与有道 `appSecret`【代码·已复核】**

- 证据：`src/services/backup.ts:22-33` 直接整份序列化 `Settings`；`Settings.ai.key`（`core/types.ts:245-249`）与 `settings.speech.youdao.appSecret`（`core/types.ts:300`）都在其中；`src/dao/settings.ts:28-40` 确认 `settings.get()` 返回完整对象、无脱敏；本地文件夹自动备份走同一路径（`services/localfile.ts:213`）。
- 与文档冲突：`HANDOVER.md` 自述「导出备份**不包含**密钥」。
- 影响：不违反 R4（密钥没上服务器），但备份一旦外传就是密钥泄露。
- 建议：导出前把两处置空，或提供「含密钥 / 不含密钥」两个入口并默认不含。

**② `hasMore === true` 时 `lastSyncAt` 仍推进到 `serverTime`，>2000 条的增量存在静默漏拉风险【代码推断·未确认·测试未覆盖】**

- 证据：`src/dao/cloudSync.ts:257-260`（`lastPushAt` 已经正确处理了 `hasMore`，但 `lastSyncAt` 无条件写 `serverTime`）；二期同构 `kcCloud.ts:250-257`。服务端是严格 `updated_at > since`（`api/_lib/inventory.ts:196-204`）。
- 推理：单次 pull 上限 `MAX_PULL_ROWS = 2000`；若云端有 5000 条增量，第一页拉 2000 条后 `lastSyncAt` 被推到 `serverTime`，剩余 3000 条在后续 pull 中**可能不再下发**。
- 测试现状：现有测试里最大的数据量是 1202 条（<2000，`hasMore=false`），**没有任何 `hasMore === true` 的用例**。
- 建议：`hasMore` 时不要把 `lastSyncAt` 推到 `serverTime`（或改成服务端游标分页 + 客户端循环 pull），并补一条 >2000 条的集成测试。

**③ 二期三张小表的云同步「已实现但没接线」【代码·已复核】**

- 证据：`api/context-words.ts` / `api/exam-history.ts` / `api/bank-questions.ts` 三条路由与 `src/dao/kcSmallCloud.ts`（`pushSmallTable/pullSmallTable/pushAllSmall/pullAllSmall`）都完整，但全仓 grep 这些函数**只有 `kcSmallCloud.ts` 自身**出现，**没有任何调用点**，也不在任何同步调度里。
- 影响：每日语境词 / 题目历史 / 题库目前**只在本机**，换设备后这些数据不会过去（而知识卡片会过去，用户会感到不一致）。
- 建议：确认是「待接线」还是「有意不接」；若接，挂到二期调度器上。

### 8.2 一致性 / 安全（次优先）

| 项 | 说明 | 证据 |
|---|---|---|
| **同步码没有加盐、没有 KDF** | `spaceKey = sha256(明文码)`。规则只要求「≥8 位且含字母数字」——像 `abcd1234` 这种码，任何拿到哈希的人都能用字典攻破。理论上若数据库泄露，弱口令空间可被枚举。**加盐对本地优先场景不容易做**（会变成「服务器也要知道盐」），可行替代是**提高口令强度要求**或用 **PBKDF2/Argon2 派生**。 | `core/syncHelper.ts:14-32`、`:60-64` |

### 8.4 已知限制（作者自己承认的）

- AI 密钥存 localStorage/IndexedDB，**清缓存会丢**；导出备份**本应**不含密钥（见 §8.1①，实际含）。
- 本地文件夹自动备份只有 Chrome/Edge 支持，Safari 降级为手动导出。
- 音标与例句靠 AI 补；纯规则解析模式下这两项为空。
- 词量上万时列表筛选是**内存过滤**，会卡（改造方向：索引游标）。
- **墓碑不会自动清理**，一直留着（占空间很小）。
- 同步冲突是后写覆盖：两设备离线各改同一个词，后同步的覆盖前面的。
- **二期「单词 → 知识点」的反向桥接没有实现**（只有「复习中途去背单词」这个单向桥接）【未确认是否有计划】。

### 8.5 未验证项（作者诚实清单，值得肯定）

真机手感、iOS 语音、添加到主屏幕、**真实 AI 密钥的端到端调用**、多设备真机同时在线——这五项**代码写了、自动化测不到**。这与项目「把踩过的坑都写成注释 + 每条规律都加护栏」的文化是一致的。

## 10. 结论

**架构上**，这是一个「把复杂度关在笼子里」的项目：技术选型极简（无框架、无 ORM、无状态服务），但每一处复杂度都配了**注释说明为什么**、**测试守住回归**、**护栏防止重犯**。分区（一期/二期）、分层（core/dao/services/ui）、分通道（一期同步/二期同步）都做到了互不拖累。

**交互上**，一期的核心是「白纸空间记忆 + 义项逐个默写」，其中最反直觉也最见功力的是三件事：**优先级绝对优先**（可预测而非随机）、**判分基于录入时固化的义项等价关系**（可离线、可解释）、**斩无确认但 8 秒可撤销**（快且不怕误触）。二期把「掌握度」做成了带**方向惩罚**的公式——它不是想算得多准，而是想抓住「盲目自信」这种最危险的状态。

**数据上**，本地 IndexedDB 是唯一主存储（10 张表、8 个版本的迁移史、三级自愈），云端是同一套 SQL 跑在 Turso 上（6 张表、复合主键、`space_key` 隔离），同步是**先拉后推 + 增量游标 + 后写覆盖 + 墓碑删除**。最漂亮的一处是「同毫秒批次推送」的处理：认识到「`updatedAt` 游标分不开同一毫秒的几百条记录」之后，改成 **`>=` 候选集 + `pushedIds` 去重 + 游标只推进到真实最大值**——这是实践中才会长出来的设计。

**需要修的问题**集中在三处：备份 JSON 里的明文密钥、`hasMore` 时游标推进可能导致的静默漏拉、二期三张小表「接口齐了但没接线」；其余多是**文档与代码的年久失修**（版本号、已删文件、未生效的设置项）。

## 11. 术语表

**架构与运行**

| 词 | 一句话解释（用本项目的实例） |
|---|---|
| 本地优先 Local-first | 先写本地 IndexedDB 并立刻生效，云同步只是后台追赶；同步失败只给一条轻提示，绝不阻断（`AI_RULES.md` R4-4） |
| PWA | 网页 + manifest + Service Worker，可「添加到主屏幕」并离线运行 |
| Service Worker | 浏览器里的后台脚本，可拦截 fetch 决定「走缓存还是走网络」；本项目手写 194 行 |
| Serverless Function | 每次请求可能落在新实例的无状态函数；本项目 `api/*.ts` 就是 |
| hash 路由 | 用 `#/list` 表示页面，切换不发请求；本项目用「精确匹配的 Map」，所以带参路由走 query |
| 分层架构 | core（纯逻辑）/ dao（数据出入口）/ services（外部世界）/ ui（界面）四层，各有硬纪律 |
| 循环依赖 | A↔B 互相 import；本项目用「构造器/注册函数注入」打破（`registerKcSyncRunner`） |
| 依赖注入 | 需要的能力从外部传进来而不是自己 import；本项目用它解循环依赖与「core 不碰 dao」 |
| 错误边界 | 把可能抛错的渲染包起来，出错给兜底页而不是白屏 |
| 单体/双期分区 | 同一个前端里一期（单词）与二期（知识点）各自独立成一套表/DAO/路由/游标 |
| 产物模拟器 | `scripts/emit-api.mjs`：在本地复现「Vercel 剥类型但不重写 import 路径」这一步 |
| BOM | 文件开头的隐藏字节；PowerShell 的 UTF8 写入会带上它，会让 Vite 的严格 `JSON.parse` 崩掉进而整页白屏 |

**数据与同步**

| 词 | 一句话解释 |
|---|---|
| IndexedDB | 浏览器内置的结构化事务数据库，本项目的**唯一主存储**（`blank-sheet-vocab` v8 / 10 张表） |
| object store / index / cursor | 表 / 字段索引 / 遍历器；**踩过的坑**：缺字段的老记录不会被该字段的索引覆盖 |
| schema 版本迁移 / `onupgradeneeded` | 版本号变高才触发的升级回调；**版本号相同就永远不会触发**，所以补表只能「抬版本号」 |
| 幂等（idempotent） | 执行多次与执行一次结果相同；本项目所有迁移都必须幂等，因为自愈修复会重跑同一段代码 |
| 墓碑删除 tombstone | 不真删、留 `deleted=1` 让别的设备也知道被删了；一期墓碑落地时真删，二期留墓碑以便复活 |
| 增量同步 delta sync | 只传变化的部分，靠时间戳游标（本项目 `since = updated_at`） |
| 游标 cursor（同步语义） | 记录「已经同步到哪」的两个时间戳：`lastSyncAt`（拉）与 `lastPushAt`（推） |
| Last-Write-Wins | 冲突时按 `updatedAt` 取大者，不问用户；代价是离线并行修改会互相覆盖 |
| `applied` / `conflicts` / `skipped` | 推送返回的三个计数：成功写入 / 因更旧被挡 / 因结构不合法被跳过 |
| 防抖 debounce | 连续变动只在停止后同步一次（本项目 5 秒） |
| 退避 backoff | 失败后等待一段时间再重试（本项目失败 60 秒后再试） |
| SHA-256 | 单向哈希；本项目把同步码变成 64 位十六进制凭据，服务器与日志都看不到明文 |
| `space_key` | 空间标识（就是同步码的哈希）；**本项目没有 spaces 表**，一行上的这一列就是全部 |
| Turso / libSQL | SQLite 的云托管与 wire 协议；本项目云端 6 张表都在上面，本地开发可指向 `file:` |
| SSRF | 拿你的服务器当跳板请求任意地址；用上游主机白名单（`AI_ALLOWED_HOSTS`）防 |
| CORS | 浏览器同源策略的显式豁免；上游 AI 不返回 CORS 头正是本项目需要代理的原因 |
| SSE / 流式透传 | 边收边发不缓冲；代理具备该能力，但本项目客户端恒 `stream: false` |
| 无状态代理 | 不写库、不写日志、不缓存、不回显请求头，密钥随请求来、用完即弃（`/api/ai-proxy`） |
| Cache First / Network First | Service Worker 的两种取数策略：静态资源用前者，页面导航用后者 |
| JSON 契约 | 提示词里规定的输出形状 + 代码里的解析与钳制（AI 不保证守约，所以必须有降级） |

**学习与内容**

| 词 | 一句话解释 |
|---|---|
| 义项 Sense / 代表义项 / aliases | 一个词的一个独立含义；判分时命中代表义项**或任一近义词**即通过 |
| 打包义项 | 「跑步，奔跑」被写成一个义项的错误写法；会导致用户答其中任何一个都判错，所以有专门的拆包函数与回归测试 |
| 词级优先级 `priority` | 用户手设 1~5，决定**背诵**先抽谁，**绝对优先** |
| 复习优先度 `reviewPriority` | 由表达式算出的实数，决定**复习**先抽谁 |
| `failRate` / `examCount` / `failCountTotal` | 失败率 = 真实累计失败 ÷ 总考核次数；分母缺失时不做除法、取默认 0.5 |
| 表达式引擎 | 用户自定义公式 + 字符集/变量白名单 + 真试算三层安全边界 |
| 确定性随机（seed / mulberry32） | 用固定种子生成可复现的伪随机序列，保证同一次会话顺序稳定 |
| 白纸 / 落点 / 抖动 / 避让区 | 满屏白底撒词；落点是归一化坐标；格内小幅随机偏移避免呆板；按钮区必须避开 |
| 答案卡 | 提交后弹出的**与普通界面同一张可编辑单词卡** + 逐框对错对照 |
| 斩 / 复活 / 撤销窗口 | 斩是 `status='chopped'` 软删；不弹确认但必须给 ≥8 秒撤销；列表页「已斩」区可永久复活 |
| 记忆环节 / 拼写环节 | 看英文填中文义项 / 看中文拼英文 |
| `hintFails` | 「用了提示就算未通过」的开关；**只对开启之后的考核生效，不回溯历史** |
| 知识点卡片 KnowledgeCard / Block | 二期的最小单位；卡片内容由 8 种块任意组合，结构自由 |
| 掌握度 mastery | 0~1 的三位小数，由自评(0.6) 与考核(0.4) 加权再减去**方向惩罚**得出；`3/1` 直接算 0（盲目自信） |
| 盲目自信 isBlindSpot | 自评明显高于考核（差 ≥0.34）；最危险状态，优先复习 |
| rubric 评分量规 | 给评分模型的 1/2/3 分判据表；目的是让不同次评分可比 |
| 每日语境词 | 每天 5 个互不相关的英文实词，只有用户确认后才参与出题，防「题目全是同一语境」 |
| 桥接 KcWordBridge | 一二期**唯一**的连接点：二期复习中途跳去一期白纸背 5 个单词 |
| 间隔重复 / SM-2 / FSRS | 主流背单词 App 的固定间隔排程算法；**本项目没有采用**，改做「可解释的优先度排序」 |

**安全**

| 词 | 一句话解释 |
|---|---|
| 方案 B | 服务器永不接触 AI 密钥：密钥只存浏览器，随请求来、用完即弃 |
| XSS | 把脚本塞进页面执行；本项目靠「渲染只走 `textContent`」结构性免疫，而不是黑名单过滤 |
