### 2. AI 分批解析（重点）

`src/services/ai.ts` 新增：

```ts
export interface ParseBatchResult {
  entries: { en: string; phonetic: string; example: string; senses: { text: string; aliases: string[] }[] }[];
  failed: boolean;
  error?: string;
}

export async function parseWordBatch(
  cfg: AiConfig,
  rawChunk: string,
  signal?: AbortSignal
): Promise<ParseBatchResult>;

export function splitIntoChunks(lines: string[], size: number): string[][];
```

**提示词模板要求**（写在代码常量里，中文 system prompt）：

- 角色：你是一个英语词库结构化助手
- 任务：把用户给的生词文本解析成严格 JSON
- 输出 schema：
  ```json
  { "words": [ { "en": "abandon", "phonetic": "/əˈbændən/", "example": "He abandoned his car.", "senses": [ { "text": "v. 放弃", "aliases": ["抛弃", "遗弃"] } ] } ] }
  ```
- 规则：
  1. 只输出 JSON，不要 markdown 代码块、不要解释
  2. 义项要**合并相近含义**：含义相近的合并为一个义项，其他说法放进 `aliases`（例如「放弃 / 抛弃 / 遗弃」合并为 `text: "v. 放弃"`，`aliases: ["抛弃","遗弃"]`）
  3. 义项保留词性前缀（n. v. adj. adv. prep. 等）
  4. 音标用国际音标带斜杠；例句要简短、能体现该词主要用法；**如果原文没有音标/例句就自己补一个合适的**
  5. 英文单词原样保留大小写，不要翻译，不要造词
  6. 原文一行一个词，输出顺序与输入一致，不要漏词、不要增加原文没有的词
- user content：`rawChunk` 原文

**调用流程**（写在 `ImportPage.ts` 或一个 `src/services/parsePipeline.ts` 里）：

```
splitIntoChunks → 逐批调用 → 每批结果立刻 append 到结果列表并落 sessionStorage（断点续传的 checkpoint）
              → 出错的批次记录 batchIndex，不中断整体流程
```

**断点续传**：
- 用一个 `importJob` 对象（存 sessionStorage，key `wordpaper.importJob`）：
  ```ts
  { id, sourceId, chunks: string[][], doneFlags: boolean[], results: ParseBatchResult['entries'][], createdAt }
  ```
- 页面上显示进度条 + 「已完成 x/y 批」
- 提供「继续解析」「重试失败批次」「放弃并清空」三个按钮
- 全部完成后自动跳合并页

**降级**：AI 解析失败（或无 Key）时，提示「是否改用规则解析」，用户确认后走 `core/parser.ts`，义项的 `aliases` 留空、音标例句留空。

### 3. 义项合并确认页 `src/ui/pages/MergePage.ts`（核心页面）

顶部统计：共 N 个词、M 个义项、其中 K 个词有多个义项。

**逐词卡片展示**，每张卡片：
- 大号英文单词 + 音标（可编辑 input）+ 例句（可编辑 input）
- 义项列表，每行一个义项：
  - 可编辑文本框（改 `text`）
  - 右侧显示 `aliases` 为灰色 chip，每个 chip 可点「×」删除，行尾「+ 近义词」按钮可添加
  - 左侧复选框（默认勾选 = `enabled`），取消勾选 = 划掉该义项（划掉后视觉上加删除线 + 变灰）
  - 「合并到上一项」按钮：把该义项的 `text` 变成上一项的 `aliases` 之一，并从列表移除
  - 删除按钮
- 卡片底部：「+ 添加义项」「斩掉此词（不入库）」

**批量操作工具条**（页面顶部固定）：
- 「全部展开 / 全部折叠」
- 「智能再合并」按钮：调 AI 对**当前所有词的义项**做一次近义合并建议（分批 100 词一批），把建议结果以高亮形式标出（建议合并的两项之间显示「≈ 建议合并」标签 + 一键接受按钮）—— **不自动改数据，必须用户点接受**
- 搜索框：按英文过滤卡片
- 「仅看多义词」开关

**底部固定操作栏**：
- 「确认入库（N 词）」→ 走 `dao.bulkUpsert`
- 「返回修改」
- 「取消本次导入」

### 4. 入库去重规则（写在 `src/core/model.ts` 或 `MergePage` 调用的 helper 里）

```ts
export function resolveConflict(existing: Word | null, incoming: Word, priorityDir: 'desc'|'asc'): 
  { action: 'insert' | 'replace' | 'keepBoth', word: Word }
```

- 库里没有该 `en` → `insert`
- 库里有：比较 `source.priority`
  - 新来源优先级更高 → `replace`：用新义项作为 `senses`，旧的全部塞进 `rawSources`
  - 新来源优先级更低或相等 → `keepBoth`：不覆盖 `senses`，把新的塞进 `rawSources`
- 入库页面在冲突时给出提示条：「3 个词已存在，其中 1 个因来源优先级更高被覆盖，2 个保留原义项（可在列表页手动采纳）」

## 验收标准

1. `npx tsc --noEmit` 零报错，`npm run build` 通过
2. 不填 API Key 也能走完整个流程（规则解析降级），能入库并在列表页看到
3. 填了 Key（用设置页里自己填的接口地址）→ 粘贴 20 行单词文本 → 分批解析 → 进度条正常 → 跳合并页
4. 合并页能：划掉一个义项、给某义项加近义词、把两个义项合并、删除一个义项、添加新义项
5. 中途刷新页面 → 重新进入录入页能提示「有未完成的导入任务」并支持继续/重试/放弃
6. 同一个词导入两次（第二次来源优先级更高）→ 义项被覆盖，旧义项进 `rawSources`；再导一次更低优先级的 → 义项不变、新的进 `rawSources`
7. 入库后 `attrs` 全为默认值、`status` 为 `unlearned`
