# 怎么用这套提示词（先读这页）

## 核心原则

**每个阶段开一次新对话。** 不要试图让 AI 一次写完整个项目——阶段越多，后半段越容易偏离前面的约定。

## 标准流程

1. 新建项目目录，`npm create vite@latest wordpaper -- --template vanilla-ts`
2. 开新对话 → 粘贴 `00_主提示词_每次必贴.md` 全文 → 再粘贴 `01_脚手架与数据层.md` 全文 → 发送
3. AI 写完 → 你按该阶段末尾的「验收标准」逐条点一遍
4. 有问题就**在同一对话里**让它改，改到全绿
5. 提交一次 git（`git init` 一次，之后每阶段一个 commit）
6. 开新对话 → 再贴 00 + 下一阶段 → 循环

> 每次都贴 00 是必须的。它锁死了技术栈、目录结构、数据模型和分层约束，只贴阶段提示词的话 AI 会自己发挥。

## 阶段顺序（有依赖，别跳）

```
01 脚手架 + 数据层        ← 地基，必须最先做，做扎实
02 设置页 + 备份 + AI服务  ← 后面的页面都要读设置（含本地文件夹自动备份）
03 录入 + 义项合并        ← 没有词就没法测后面
04 单词列表页
05 背诵白纸页            ← 核心特色
06 记忆 + 拼写环节        ← 规则最密，验收最细
07 复习页
08 自建转发脚本          ← 独立小项目，可选；直连能用就完全不用管
```

01~07 是主项目，08 是可选附加项。

## 几个实操建议

- **先跑通 01~04**，此时你已经有了一个能录入、能看、能改属性的词库工具，可以用起来看看顺不顺手，再决定 05 之后的交互要不要调整
- **每阶段结束让 AI 汇报改了哪些文件**，你扫一眼有没有动到不该动的地方（比如页面里出现了 `indexedDB`）
- **遇到 AI 反复改不对的地方**，把出错的现象和控制台报错原样贴给它，比描述"不行"有效得多
- **阶段 06 最容易出偏差**（规则最密）。验收时重点盯：未通过封顶逻辑、必抽规则、答案卡必须点击才继续
- 每阶段一个 git commit，写坏了能 `git checkout` 回去

## AI 怎么接

就是插件里最常见的那种：**代码只留一个接口位，地址和密钥由你自己填**。

| 填什么 | 效果 |
|---|---|
| `https://api.deepseek.com` + 官方密钥 | 直连官方（若被跨域拦，看下面） |
| 某个中转/代理地址 + 对应密钥 | 走中转，通常能绕开跨域 |
| 自建的 worker 地址（阶段 08） | 完全自己掌控 |

代码里不做任何厂商判断，只保证 DeepSeek 官方格式可用，其他 OpenAI 兼容服务能填通就用。
**不填密钥就是纯离线**，走规则解析，功能一样能跑。

## 数据存在哪

- **主存储**：浏览器自己的仓库（IndexedDB），就在你这台电脑上，不联网
- **自动备份**（阶段 02）：可以连接一个你自己选的本地文件夹，之后每次改动自动往里写一个 `wordpaper-data.json`。清缓存、重装浏览器都不怕
- **手动导出**：设置页随时导出 json，存网盘也行

三者互不影响，建议至少开一个自动备份。

## 已知限制（提前知道，别到时候觉得是 bug）

- Key 存在浏览器 localStorage，清缓存会丢；页面不能分享给他人（你自建的转发地址也不能公开）
- 本地文件夹自动备份只有 Chrome / Edge 这类较新浏览器支持；Safari 不支持，会降级成手动导出
- 音标例句第一版靠 AI 补，规则解析模式下这两项为空（后续可加离线词典）
- 单词量到上万时，列表页的筛选是内存过滤，会有卡顿（代码里已注明改造方向）
- Worker 的限流是单实例内存计数，多实例部署会失效
