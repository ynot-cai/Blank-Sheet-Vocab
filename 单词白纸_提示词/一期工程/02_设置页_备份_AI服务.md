## 任务

### 1. `src/services/ai.ts`

**接法：留一个通用接口位，地址和密钥由用户自己填**（插件里最常见的做法）。

```ts
export interface AiConfig { endpoint: string; model: string; key: string; }

export async function chatComplete(cfg: AiConfig, messages: {role:'system'|'user';content:string}[], opts?: { jsonMode?: boolean; timeoutMs?: number }): Promise<string>;

export async function testConnection(cfg: AiConfig): Promise<{ ok: boolean; message: string }>;
```

实现要点：
- **地址规范化**（关键，兼容各种填法）：
  ```ts
  function normalizeEndpoint(raw: string): string {
    let s = raw.trim().replace(/\/+$/, '');           // 去掉结尾斜杠
    if (s.endsWith('/chat/completions')) return s;    // 用户填了完整路径
    return s + '/chat/completions';                   // 其余一律补上
  }
  ```
  这样用户填 `https://api.deepseek.com`、`https://api.deepseek.com/v1`、或中转/代理给的完整地址都能用。**不要写任何厂商判断分支。**
- 请求头：`Content-Type: application/json`、`Authorization: Bearer ${key}`
- body：`{ model, messages, stream: false }`；`jsonMode` 为真时加 `response_format: { type: 'json_object' }`
- **JSON 模式降级**：若带 `response_format` 的请求失败（部分中转不支持），自动重试一次不带该字段，并在注释里说明原因
- 用 `AbortController` 做超时（默认 60s），超时抛明确错误
- 错误处理分层，抛出人类可读消息：
  - 网络失败 / CORS → 「连不上，请检查接口地址和网络。浏览器直连很多服务会被跨域拦截，这种情况请填一个中转/代理地址」
  - 401 → 「密钥无效或未填写」
  - 404 → 「模型名或接口地址不对」
  - 429 → 「触发限流，请稍后重试」
  - 返回体无 `choices[0].message.content` → 「返回内容为空，可能该服务不兼容 OpenAI 格式」
- `testConnection` 发一条极短 prompt，成功返回 `{ok:true}`，失败返回 `{ok:false, message}`（**不抛异常**，供设置页直接展示）
- 注释写明：密钥只存在本机浏览器 localStorage，每台设备各填各的，不上传也不同步

### 2. `src/services/backup.ts`

```ts
export interface BackupFile {
  version: 1;
  exportedAt: number;
  words: Word[];
  sources: Source[];
  settings: Settings;
}
export function exportBackup(): Promise<void>;      // 组装 → Blob → 触发下载，文件名 单词白纸备份_YYYYMMDD_HHmm.json
export function importBackup(file: File, mode: 'merge' | 'replace'): Promise<{ words: number; sources: number }>;
```

- `merge`：按 `en + sourceId` 判重，已存在则跳过（不动），不存在则插入
- `replace`：先 `clearAll()` 再全量写入，**执行前必须由调用方弹二次确认**
- 导入时做 schema 校验：version 不匹配或结构不对，抛「备份文件格式不正确」
- 导入的 settings 与 `DEFAULT_SETTINGS` 深合并，缺字段补默认

### 3. `src/core/parser.ts`（规则解析兜底）

```ts
export interface ParsedEntry { en: string; senses: string[]; }
export function parseText(text: string, opts: { fieldSep: string; senseSep: string }): ParsedEntry[];
```

- 逐行处理，跳过空行和 `#` 开头注释
- 字段分隔符 `auto` 时按优先级自动探测：Tab > 连续 2 个以上空格 > 逗号 > 单个空格
- 第一段是英文单词（去掉行首序号如 `1.` `12、`），剩余段按 `senseSep` 切成多个义项
- 义项保留原始词性前缀（`n.` `v.` `adj.` `adv.` `prep.` 等）
- 单词非法（含中文、长度 > 50、含空格）的行收集到返回值之外的 `errors` 里 —— 改为返回 `{ entries: ParsedEntry[]; errors: { line: number; raw: string; reason: string }[] }`

### 5. 本地文件夹自动备份（新增，`src/services/localfile.ts`）

> 目的：解决「清浏览器缓存导致数据全丢」。**数据本身就在本地，这个功能是给它再加一份你看得见摸得着的副本。**

```ts
export function isSupported(): boolean;
export function isLinked(): boolean;
export async function linkFolder(): Promise<boolean>;   // showDirectoryPicker，用户选一个文件夹
export async function unlink(): Promise<void>;
export async function syncNow(): Promise<void>;         // 立即写一次 wordpaper-data.json
export async function restoreFromFile(): Promise<boolean>;
export function onDataChanged(): void;                  // 数据变动后调用，内部防抖 2s 自动同步
```

实现要点：
- 用 `showDirectoryPicker()` 拿到 `FileSystemDirectoryHandle`，把它**存进 IndexedDB**（handle 可结构化克隆），下次不用重选
- 写入流程：`getFileHandle('wordpaper-data.json', { create: true })` → `createWritable()` → 写 `JSON.stringify(backup)` → `close()`
- 内容与 `services/backup.ts` 的 `BackupFile` 结构**完全一致**（words / sources / settings），两个功能共用一份序列化函数
- **自动同步时机**：每次 DAO 写入成功（bulkUpsert / updateAttrs / chop / revive / 设置变更）后调 `onDataChanged()`，内部防抖 2 秒合并写入。**同步失败只 console.warn + 一次轻提示，绝不阻断正常操作**
- **权限恢复**：浏览器重启后首次访问，读文件前先 `queryPermission` / `requestPermission`；权限需用户手势时，页面顶部显示一条黄条「点击恢复与本地文件夹的连接」，点击后重新授权再自动读一次
- **降级**：`isSupported()` 为 false（Safari / 旧浏览器 / 非 HTTPS 且非 localhost）时，隐藏整个连接入口，改为提示「当前浏览器不支持自动备份，请定期手动导出json」
- 设置页 F 区新增一组 UI：
  - 未连接：一个「连接本地文件夹（自动备份）」按钮 + 说明「选一个文件夹，之后每次改动会自动往里面写一个数据文件，清缓存也不怕」
  - 已连接：显示文件夹名 + 「立即备份一次」「从文件恢复」「断开连接」+ 上次同步时间
  - 一个开关：「关闭页面前提醒我导出备份」（默认开；关页面时若距上次手动导出超过 7 天，弹确认框提醒）

> 注意：浏览器不允许网站未经允许写任意路径，所以**必须由用户主动选一次文件夹**，这是安全机制，不是缺陷。

## 验收标准

1. `npx tsc --noEmit` 零报错，`npm run build` 通过
2. 设置页 5 个星号参数改动后刷新页面仍保留
3. AI 分区不填 Key 点「测试连接」→ 红字提示，不崩
3b. 接口地址分别填 `https://api.deepseek.com`、`https://api.deepseek.com/v1`、一个带 `/chat/completions` 的完整地址 → 三种都不会拼错成重复路径（把最终请求的完整 URL 打到 console 里自查）
3c. 把接口地址清空或填乱码 → 点测试连接给出可读错误，不白屏
4. 优先度表达式填 `failCount *` （非法）→ 试算给出红字提示，保存被拦
5. 导出备份能得到 json；清库后导入（合并）能恢复词和设置
6. `core/parser.ts` 用这段样例验证能正确切分（写在 `src/dev/selftest.ts` 里）：
   ```
   abandon  v. 放弃；抛弃；遗弃
   ability	n. 能力；才能
   # 这是注释
   absorb  v. 吸收 / 吸引
   ```
   期望：3 条，义项分别是 3 / 2 / 2 个
7. 点「连接本地文件夹」选一个空文件夹 → 文件夹里立刻出现 `wordpaper-data.json`；改一个单词的属性 → 2 秒后文件里的内容跟着变（用记事本打开看）
8. 关掉浏览器再打开 → 顶部出现「点击恢复连接」黄条 → 点一下 → 恢复成功且数据一致
9. 手动清掉浏览器缓存 → 数据没了 → 点「从文件恢复」→ 词和设置全回来
