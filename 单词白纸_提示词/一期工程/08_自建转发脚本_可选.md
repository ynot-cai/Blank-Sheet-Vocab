# 阶段 08：可选的自建转发脚本（独立于前端，不做也能正常用）

> 这是一个**独立小项目**，单独目录 `wordpaper-proxy/`。
> **前端代码零改动**——用户只要把部署出来的地址填进设置页的「接口地址」就行。
> 如果用户填的官方地址能直连通，这一整个阶段可以跳过。

## 背景（写代码前先读懂）

浏览器直连大模型 API 常见问题：
1. 很多服务不返回 CORS 头，浏览器会拦掉请求
2. 前端填的 Key 等于公开在页面里

这个脚本的作用：给用户多一个选择——自己部署一个转发口，网站连它，它去连真正的服务，并带上 CORS 头。

## 任务：一份 Cloudflare Worker 脚本

### 文件
```
wordpaper-proxy/
├─ src/index.ts        Worker 主逻辑
├─ wrangler.toml
├─ package.json        scripts: deploy / dev / tail
└─ README.md           部署步骤（见下）
```

### `src/index.ts` 行为

接收标准 OpenAI 兼容请求：
```json
POST { "model": "deepseek-chat", "messages": [...], "stream": false }
Authorization: Bearer <用户填的密钥>
```

流程：
1. `OPTIONS` 预检 → 返回 204 + 全套 CORS 头
2. 非 POST → 405
3. **口令校验**（可选）：若环境变量 `ACCESS_TOKEN` 非空，则要求请求头 `Authorization: Bearer` 的值与之相等，否则 403 `{ error: 'forbidden' }`
4. 上游地址 = 环境变量 `UPSTREAM_BASE`（默认 `https://api.deepseek.com`），目标 URL = `UPSTREAM_BASE.replace(/\/+$/,'') + '/chat/completions'`
5. 上游密钥：环境变量 `UPSTREAM_KEY` **若设置了就用它**；没设置则**原样透传**请求里的 `Authorization`（透传模式，用户填什么就发什么）
6. 转发：method/body 原样；删除 `origin` / `host` 头；设置 `Content-Type: application/json`
7. 上游响应**原样返回**（含 status、body，支持流式透传），并加 CORS 头
8. 超时 `AbortSignal.timeout(120000)`
9. 全包 try/catch，异常返回 502 `{ error: message }`

CORS 头（所有响应都带）：
```
Access-Control-Allow-Origin: *        // 或按 ALLOW_ORIGIN 环境变量指定
Access-Control-Allow-Methods: POST, OPTIONS
Access-Control-Allow-Headers: Content-Type, Authorization
Access-Control-Max-Age: 86400
```

**安全约束（必须遵守）**
- 脚本里不得硬编码任何真实密钥、上游地址、域名白名单，全部走环境变量
- 响应里**不得回显**任何密钥内容
- 不得透传上游返回的 `Authorization` 头
- 极简限流：内存 Map 按 `CF-Connecting-IP` 计数，单 IP 每分钟 > 60 次返回 429（注释说明：单实例内存计数，多实例需换 Durable Object / KV）

### `wrangler.toml`
```toml
name = "wordpaper-proxy"
main = "src/index.ts"
compatibility_date = "2024-01-01"

[vars]
UPSTREAM_BASE = "https://api.deepseek.com"
# ACCESS_TOKEN = ""   # 建议设置，但要用 secret 而不是 vars
# ALLOW_ORIGIN = "*"
```
注释说明：`UPSTREAM_KEY` 和 `ACCESS_TOKEN` 用 `wrangler secret put` 设置，不要写进文件。

### `README.md` 要写清

1. 什么时候需要它：直连报跨域错误时才需要；能直连就不用装
2. 部署步骤：`npm i` → `npx wrangler login` → （可选）`npx wrangler secret put UPSTREAM_KEY` → （建议）`npx wrangler secret put ACCESS_TOKEN` → `npm run deploy` → 得到 `https://xxx.workers.dev`
3. 前端怎么用（**一行就够**）：设置页「接口地址」填 `https://xxx.workers.dev`，「密钥」填你设的 ACCESS_TOKEN（或你自己的上游密钥，取决于是否配了 UPSTREAM_KEY）。**前端不用改任何代码**
4. 换服务：改 `UPSTREAM_BASE` 即可，任何 OpenAI 兼容格式都行
5. 安全提醒：这个转发口是公开的，任何知道地址（+口令）的人都可能用你的额度。**务必设 `ACCESS_TOKEN`，不要把地址发到公开场合**
6. 备选：Vercel / Netlify 也能跑，把 `src/index.ts` 改写成对应签名（导出一个 `POST` 函数）即可，前端调用方式不变

## 验收标准

1. `npx tsc --noEmit` 零报错
2. `npx wrangler dev` 本地起得来
3. curl 自测四件事（写进 README）：
   - `OPTIONS` → 204 且带 CORS 头
   - 口令不匹配 → 403
   - 正确口令 + 有效上游密钥 → 200 且返回模型输出
   - 上游密钥错误 → 上游的 401 被原样透传
4. 前端设置页接口地址填这个 worker 地址、密钥填口令 → 点「测试连接」→ 绿字成功
