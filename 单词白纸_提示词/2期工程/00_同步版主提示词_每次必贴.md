## 1. 本阶段一句话目标

让同一个人（就是使用者自己）的**手机、平板、电脑**通过互联网访问同一份单词数据。
**不对外开放注册**，不做多用户社区。自用工具，零成本、零运维。

密钥仍存浏览器（**方案 B**），服务器永不接触用户密钥。

| 项 | 选型 | 说明 |
|---|---|---|

**架构总览**

```
手机/平板/电脑浏览器
  ├─ 单词数据：本地 IndexedDB（主）  ← 离线可用，秒开
  ├─ 同步：后台静默 → Vercel Function → Turso 数据库
  └─ AI 密钥：只存浏览器（方案 B），直连 AI 或经无状态代理
```

**禁止引入**：Docker、Nginx、Fastify、Express 服务器、Prisma、TypeORM、Redis、任何前端框架。

## 3. 核心设计一：本地优先（Local-first）—— 最重要

**这是整个架构的基石，也是应对"Vercel 在国内访问可能慢"的杀手锏。**

- 所有单词数据**主存在浏览器 IndexedDB**，打开应用**立刻可用**，不等网络
- 同步是**后台静默**的：数据变动后防抖几秒，悄悄同步到云端
- **同步失败绝不阻断使用**：断网、Vercel 打不开、Turso 超时 → 用户照样能背单词，只是顶部一条轻提示
- 换设备时：填同一个同步码 → 从云端拉回数据

> 这意味着：即使 Vercel 偶尔访问慢或打不开，用户体验**几乎不受影响**——因为根本不依赖实时网络。

---

## 4. 核心设计二：同步码（替代账号注册）

使用者自己在设置页起一个**同步码**（比如 `my-word-2026`），所有设备填同一个码，就访问同一个数据空间。

```
同步码 ──SHA-256──> spaceKey ──> Turso 用它隔离数据
   │                                   │
   └─ 只存浏览器                        └─ 服务器只存哈希值
```

**为什么这样**
- 不需要邮箱注册 → 零用户管理、零密码找回
- 服务器只存哈希，不知道明文同步码
- 将来若要公开：把 `spaceKey` 换成 `userId`，业务代码几乎不动

**安全约束**
- 服务器**只存** `spaceKey`（同步码的 SHA-256 哈希），**绝不存明文**
- 所有 SQL 必须带 `WHERE space_key = ?`（DAO 层强制）
- 前端提示：同步码至少 8 位字母数字

---

## 5. 核心设计三：方案 B（AI 密钥存浏览器）

**服务器永不接触 AI 密钥。** 这是安全底线，任何时候都不要破例。

- 密钥只存在浏览器 `localStorage` / IndexedDB
- 调用 AI 时：浏览器**直连**用户填的接口（首选）；若被 CORS 拦 → 走**无状态代理**转发
- 代理只读请求头、用完即弃，**不写库、不写日志、不缓存**
- 代码里**不得有任何"存储密钥"的逻辑**，数据库**不得有存密钥的表**

## 7. Turso 数据模型（`api/_lib/db.ts` 里建表）

```sql
CREATE TABLE IF NOT EXISTS words (
  id TEXT PRIMARY KEY,
  space_key TEXT NOT NULL,        -- SHA-256(同步码)
  en TEXT NOT NULL,
  phonetic TEXT,
  example TEXT,
  senses TEXT NOT NULL,           -- JSON 字符串
  source_id TEXT,
  raw_sources TEXT,               -- JSON
  attrs TEXT NOT NULL,            -- JSON
  status TEXT NOT NULL,
  learn_order INTEGER,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  deleted INTEGER DEFAULT 0       -- 软删除，供同步
);
CREATE INDEX IF NOT EXISTS idx_words_space ON words(space_key);
CREATE INDEX IF NOT EXISTS idx_words_updated ON words(space_key, updated_at);

CREATE TABLE IF NOT EXISTS sources (
  id TEXT PRIMARY KEY,
  space_key TEXT NOT NULL,
  name TEXT NOT NULL,
  priority INTEGER NOT NULL,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  deleted INTEGER DEFAULT 0
);
CREATE INDEX IF NOT EXISTS idx_sources_space ON sources(space_key, updated_at);
```

**没有 `users` 表，没有存 AI 密钥的表。** 这是安全性的来源。

## 8. API 设计

同步码由前端 SHA-256 后放请求头 `X-Space-Key`。

| 路由 | 方法 | 说明 |
|---|---|---|
| `/api/health` | GET | 健康检查（不需要 spaceKey） |
| `/api/sync/pull?since=<ts>` | GET | 增量拉取 words + sources（含软删除） |
| `/api/sync/push` | POST | 批量推送（upsert），**单批 ≤ 500 条** |
| `/api/ai-proxy` | POST | 无状态 AI 转发 |

**同步策略**（个人自用，设备少，冲突极少）：
- 增量同步，按 `updatedAt` 时间戳
- 冲突：**后写覆盖**（last-write-wins）
- 删除用**软删除**（`deleted=1`），保证其他设备能感知

## 9. Vercel 平台限制（必须规避）

| 限制 | 应对 |
|---|---|
| 请求体上限 **4.5 MB** | 批量推送**每批 ≤ 500 条**，前端分批处理 |
| 函数默认超时 300 秒（Hobby） | 足够；AI 代理另设 `maxDuration: 60` 即可 |
| Serverless 无状态 | Turso client 放**模块级**复用，不要每次请求新建 |
| 冷启动 | 首次请求可能慢 1~2 秒，前端要有超时重试，但不阻断 |

---

## 10. 硬约束（违反即不合格）

1. **服务器永不接触 AI 密钥**：不得有存储密钥的逻辑，不得有存密钥的表。
2. **只存哈希**：同步码只能以 SHA-256 哈希落库，明文禁止写库、禁止写日志。
3. **空间隔离**：所有 SQL 必须带 `WHERE space_key = ?`，DAO 层强制。
4. **本地优先，同步可选**：断网时应用必须能用（读本地），同步失败只轻提示、绝不阻断。
5. **批量分批**：同步推送每批 ≤ 500 条，规避 Vercel 4.5MB 请求体限制。
6. **不要推翻现有前端**：只做增量改造，现有页面、DAO 接口、数据模型尽量兼容。
7. **TypeScript strict**、**零魔法数字**（集中在 `config.ts`）、单文件超 300 行就拆。
