## 背景（务必读懂）

浏览器直连 AI 服务时，很多厂商不返回 CORS 头，请求会被拦截。所以需要一个代理转发。

**但代理必须是无状态的**：只做"转发 + 加 CORS 头"，**绝不存储密钥、绝不写数据库、绝不写日志、绝不缓存**。用户密钥随每次请求的 `Authorization` 头过来，用完即弃。

这样即使服务器被攻破，攻击者**也拿不到任何人的密钥**——因为服务器上根本没有。

## 任务：`api/ai-proxy.ts`

```ts
POST /api/ai-proxy
```

### 请求
- 头：`X-Target-Url`（目标 AI 完整地址，如 `https://api.deepseek.com/chat/completions`）、`Authorization`（用户自己的密钥）、`Content-Type`
- body：标准 OpenAI 兼容请求体（原样转发）

### 处理流程

1. **来源校验**：检查 `Origin` / `Referer`，必须在 `ALLOWED_ORIGIN` 白名单内，否则 403
   （**防止别人拿你的代理当免费转发**；自用场景也要加，因为代理是公网可访问的）
2. **目标地址校验**：`X-Target-Url` 必须是合法 **HTTPS** URL，否则 400
3. 转发：
   - method、body 原样
   - 头里**删除** `origin`、`host`、`referer`、`cookie`、`x-forwarded-*`
   - **保留** `authorization`、`content-type` 及 AI 服务需要的头
4. **超时 60 秒**（`AbortSignal.timeout(60_000)`）
5. 上游响应原样返回（含 status、body）
   - **若上游是流式（SSE / `text/event-stream`）**：直接 pipe 流，**不要缓冲**成一次性返回
   - 设置 `Cache-Control: no-store`
6. 加 CORS 响应头
7. 全包 try/catch，异常返回 502 `{ error: message }`

### 绝不许做的事（写完自己逐条检查）

- ❌ 把 `authorization` 头的值写入任何存储（数据库、文件、全局变量）
- ❌ 写数据库（本代理**不连接** Turso）
- ❌ 写日志（**日志里禁止出现 authorization / api key / bearer**，最多打"转发了一次请求"）
- ❌ 缓存响应
- ❌ 把请求头回显给客户端
- ❌ 记录任何与密钥相关的信息

### `vercel.json` 补充配置

为 AI 代理单独设超时（比同步 API 长）：

```json
{
  "functions": {
    "api/ai-proxy.ts": { "maxDuration": 120 },
    "api/**/*.ts": { "maxDuration": 60 }
  }
}
```

注释说明：Hobby 计划 `maxDuration` 上限 300 秒；AI 解析整批文本可能较慢，给 120 秒。

## 前端改造（`src/services/ai.ts`）

现有 AI 调用改**双路径自动切换**：

```ts
export interface AiConfig {
  endpoint: string;    // 用户填的 AI 接口地址
  model: string;
  key: string;         // 用户密钥，只存浏览器
  useProxy?: boolean;  // 是否走代理（默认自动判断）
}
```

调用流程：
1. **先尝试浏览器直连**用户填的 `endpoint`
2. 若失败且错误是 **CORS / 网络类型** → **自动切换**代理：
   `POST {cloudApiBase}/api/ai-proxy`，头带 `X-Target-Url: <用户 endpoint>`、`Authorization: Bearer <用户 key>`
3. 代理也失败 → 清晰提示："直连和代理都失败了，请检查接口地址、密钥或网络"
4. 设置页显示当前路径（直连 / 代理），允许手动强制走代理

**注释写明**：无论走哪条路，密钥都来自浏览器本地存储，服务器（含代理）不保存。

## 验收标准

1. `npx tsc --noEmit` 零报错，`npx vercel dev` 能启动
2. **功能验证**：不填/错填密钥 → 上游 401 被原样透传，前端能看到 401
3. 填正确密钥 → 能拿到 AI 回复（**直连**路径成功）
4. **代理路径验证**：手动强制走代理 → 能正常拿到 AI 回复
5. **来源校验**：用 curl 从非白名单 Origin 请求代理 → 403
6. **无状态验证（最关键，逐条确认）**：
   - 代码层面：全文搜 `authorization`、`key`、`token`，确认**没有任何**写入数据库/文件/全局变量的逻辑
   - 运行层面：发几次请求后查 Vercel 日志，**搜不到任何密钥明文**
   - 数据库层面：`api/ai-proxy.ts` **根本没有引入** `getDB()` / 不连接 Turso
7. 流式响应（若 AI 返回 SSE）能透传，不被缓冲成一次性返回
8. 超时验证：把 `X-Target-Url` 指向一个慢地址 → 60 秒后返回超时错误（不是无限等待）
