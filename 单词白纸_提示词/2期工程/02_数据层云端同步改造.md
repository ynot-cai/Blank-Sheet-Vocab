# 阶段 02：前端数据层改造（本地 + 云端双写）

> 前置：阶段 01 已完成后端，API 可用。**本阶段最容易把现有功能改坏，务必小心。**

## 核心原则

**本地优先（Local-first）**：所有操作先写本地 IndexedDB（保证立刻生效、断网能用），再异步同步到云端。**同步失败绝不阻断用户操作。**

## 任务

### 1. 新增 `src/core/config.ts` 云端配置项

在 `DEFAULT_SETTINGS` 里加：

```ts
cloud: {
  enabled: false,        // 是否开启云同步
  apiBase: '',           // 后端地址，如 https://wordpaper.vercel.app（Vercel 域名，不要带 /api）
  syncCode: '',          // 同步码（明文，只存浏览器，永不发服务器）
  lastSyncAt: 0,         // 上次同步时间戳
  autoSync: true,        // 自动同步（每次数据变动后防抖同步）
}
```

导出工具函数（放 `src/core/syncHelper.ts` 或 config 里）：

```ts
export async function sha256(text: string): Promise<string>;   // Web Crypto API，返回 64 位十六进制
export function getSpaceKey(syncCode: string): Promise<string>; // = sha256(syncCode)
```

**注释写明**：明文同步码只存在浏览器 localStorage，发请求时只发哈希，服务器不知道明文。

### 2. 新增 `src/dao/cloudSync.ts`

```ts
export interface SyncResult { pulled: number; pushed: number; conflicts: number; error?: string; }

export async function testConnection(): Promise<{ ok: boolean; message: string }>;
export async function pull(since: number): Promise<{ words: Word[]; sources: Source[]; serverTime: number }>;
export async function push(words: Word[], sources: Source[]): Promise<{ applied: number; conflicts: number }>;
export async function syncOnce(): Promise<SyncResult>;
```

- 请求头统一带 `X-Space-Key: await getSpaceKey(syncCode)`、`Content-Type: application/json`
- **超时 15 秒**，用 `AbortController`，超时算失败但不抛异常到 UI
- **分批推送（必须）**：Vercel 请求体上限 4.5 MB，`push` 内部要把待推送数据按**每批 ≤ 500 条**切分，逐批调用 `/api/sync/push`，最后汇总结果。**首次全量同步（几千词）尤其需要这个**
- 网络错误 / 5xx / 超时 → 返回 `{ error: '...' }`，**不抛异常**（调用方决定怎么提示）
- 401 → 明确提示"同步码无效或服务器拒绝"
- 所有失败都要 console.warn 但不阻断
- **重试**：同步失败时做一次简单重试（间隔 2 秒，最多 1 次），仍失败就交给下次防抖同步

### 3. 改造现有 DAO 为双写

在现有 `src/dao/words.ts` 的每个写操作（`bulkUpsert` / `updateSenses` / `updateAttrs` / `chop` / `revive`）里：

1. **先写本地 IndexedDB**（现有逻辑不动）
2. 若 `settings.cloud.enabled && settings.cloud.autoSync` → 调 `scheduleSync()`

```ts
// src/dao/syncScheduler.ts
export function scheduleSync(): void;   // 防抖 5 秒，合并多次变动为一次同步
```

- 同步是**后台静默**的，不在 UI 上打断用户
- 同步成功更新 `settings.cloud.lastSyncAt`
- 同步失败：在页面顶部显示一条**不打断操作的轻提示**（如"云同步失败，数据已存本地"），5 秒后自动消失

### 4. 同步流程（`syncOnce` 的实现）

```
1. pull(since = lastSyncAt)
   ├─ 拿到云端增量（含 deleted=1 的）
   ├─ 云端 updatedAt > 本地 updatedAt → 用云端覆盖本地
   └─ 本地有、云端没有（新设备首次）→ 保留本地，等 push
2. push(本地所有 updatedAt > lastSyncAt 的词)
   └─ 云端按后写覆盖处理
3. 更新 lastSyncAt = serverTime
```

**冲突策略（第一版，简单优先）**：后写覆盖（last-write-wins）。注释说明：个人多设备场景冲突极少，将来可升级为冲突提示。

**软删除同步**：云端返回 `deleted=1` 的词 → 本地执行删除（或标记 `status='chopped'` / 真的从本地移除，二选一，注释说明选了哪个及原因）。

### 5. 设置页新增「云同步」分区

- 开关「启用云同步」
- 「后端地址」输入框（提示：填你的 Vercel 域名，如 `https://wordpaper.vercel.app`，**不要带 `/api`**，代码里会自动拼接）
- 「同步码」密码框（提示：**所有设备填同一个码就能同步**；至少 8 位字母数字；忘记无法找回，请自己记牢）
- 按钮：
  - 「测试连接」→ 调 `testConnection`，绿/红 Toast
  - 「立即同步」→ 调 `syncOnce`，显示结果（拉取 N 条 / 推送 M 条）
  - 「强制覆盖」→ 二次确认后，用本地数据全量覆盖云端（或反过来，给两个选项）
- 显示状态：「上次同步：3 分钟前」/「从未同步」
- 醒目提示文案：
  > 同步码只保存在这台设备的浏览器里，我们的服务器只存它的哈希值，不知道你的明文同步码。
  > 换设备时在新设备填同一个同步码即可同步。清缓存或忘记同步码将无法恢复数据，请定期导出备份。

### 6. 首次启用引导

用户第一次打开「启用云同步」时，弹一个说明框，讲三件事：
1. 同步码是什么、怎么起（自己编一个字符串，别用简单密码）
2. 所有设备填同一个码
3. **一定要先导出一次备份**（因为清缓存会丢同步码）

## 验收标准

1. `npx tsc --noEmit` 零报错，`npm run build` 通过
2. **断网验证（最重要）**：关掉后端（或断网）→ 所有原有功能（录入、背诵、记忆、复习、列表）照常可用，只是顶部提示"云同步失败"，**没有任何功能报错或白屏**
3. 开启云同步 → 填后端地址 + 同步码 → 点「测试连接」→ 绿字成功
4. 点「立即同步」→ 本地词库上传到云端（后端数据库能查到记录）
5. **多设备验证**：用浏览器的**无痕窗口**（相当于另一台设备）打开同一地址，填同一个同步码 → 能拉到主窗口的词库
6. **隔离验证**：换一个同步码 → 拉不到前一个码的数据
7. 在主窗口改一个单词的属性 → 5 秒后无痕窗口同步能看到变化
8. 同步失败时不弹窗打断，只是顶部轻提示后自动消失
9. 代码确认：`cloudSync.ts` 里**没有任何地方**把明文 `syncCode` 发出去（只发 SHA-256 哈希）
