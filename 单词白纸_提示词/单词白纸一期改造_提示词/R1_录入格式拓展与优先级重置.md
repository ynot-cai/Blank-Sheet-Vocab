> 前置：已贴 `00_同步版主提示词_每次必贴.md`。
> 本阶段只做两件事：**①录入支持更多文件格式 ②彻底重建优先级系统**。

---

## 第一部分：录入格式拓展

### 1.1 支持的文件类型

| 格式 | 扩展名 | 解析方案 |
|---|---|---|
| 纯文本 | `.txt` | 现有逻辑（直接读文本） |
| Word 文档 | `.docx` | `mammoth` 的 `extractRawText`（保留换行，够用于单词表；表格内容会退化为纯文本，可接受） |
| PDF | `.pdf` | `pdfjs-dist` 提取文本层 |

### 1.2 装依赖

```bash
npm install mammoth pdfjs-dist
```

**关键要求：动态 import，不要静态引入。**
这两个库体积大，不能在首屏加载。只在用户真的选了 docx/pdf 时才 `await import('mammoth')` / `await import('pdfjs-dist')`。

### 1.3 `src/services/fileParse.ts`（新增）

```ts
export type ParsedFile = {
  name: string;
  type: 'txt' | 'docx' | 'pdf';
  text: string;
  warnings: string[];      // 如"PDF 第 3 页无文本层"
};

export async function parseFile(file: File): Promise<ParsedFile>;
export function isSupported(file: File): boolean;
```

**实现要点**：
- `txt`：`file.text()`，注意编码（优先 UTF-8，乱码时提示）
- `docx`：`const mammoth = await import('mammoth'); const r = await mammoth.extractRawText({arrayBuffer}); r.value`
- `pdf`：
  - `const pdfjs = await import('pdfjs-dist')`
  - worker 配置：`pdfjs.GlobalWorkerOptions.workerSrc = (await import('pdfjs-dist/build/pdf.worker.min.mjs?url')).default`
  - 逐页 `getTextContent()`，拼接 `item.str`，页间加分隔
  - **检测无文本层**：某页提取到的文本长度 < 阈值（如 10 字符）→ 记录 warning「第 N 页可能是扫描件，无文本层」
- 解析出的文本末尾统一规范换行

### 1.4 录入页 UI 改造

**上传区**：
- 支持点选 + 拖拽
- `accept=".txt,.docx,.pdf,text/plain,application/pdf,..."`
- 支持**多选**（一次选多个文件，逐个解析）
- 每个文件显示：文件名 / 类型图标 / 大小 / 解析状态（待解析→解析中→已解析 N 行 / 失败原因）
- 解析失败的文件单独显示错误，不影响其他文件

**解析后**：
- 文本进入现有的「文本预览 / 编辑框」（可手动修正）
- 然后走**现有的 AI 解析流程**（阶段 03 的 parse，**不要重写**）
- 若解析出 warning，在结果页顶部展示黄条提示

**扫描件 PDF 提示**：
若整份 PDF 基本无文本层 → 明确提示「这份 PDF 像是扫描图片，无法提取文字。请换用有文字的 PDF，或先用 OCR 工具转成 txt」。**本项目不做 OCR。**

## 第二部分：优先级系统重置（重点）

### 2.1 现在的毛病

优先级此前只是来源（source）的一个字段，抽词时没真正生效，等于"名存实亡"。本阶段彻底重建。

### 2.2 新规则（用户明确要求）

1. **每次录入都可以选择"优先级"**
2. **优先级高的单词，优先被「背诵」抽中——这是绝对优先，不是概率高**
3. **多次录入相同单词且优先级不同时，询问是否覆盖**

### 2.3 数据模型

**词级优先级**（不是来源级）：

```ts
interface Word {
  // ... 现有字段
  priority: number;   // 1~5，5 为最高，默认 3
}
```

- 每次录入是一个「批次」，批次有一个优先级选择
- 该批次录入的词，继承这个优先级写入 `word.priority`
- 数据库：`words` 表新增 `priority INTEGER DEFAULT 3`

**迁移**（Turso / SQLite）：
```ts
// 检查列是否已存在，不存在才 ADD COLUMN
const cols = await db.execute("PRAGMA table_info(words)");
if (!cols.rows.some(r => r.name === 'priority')) {
  await db.execute("ALTER TABLE words ADD COLUMN priority INTEGER DEFAULT 3");
}
```
（SQLite 的 `ADD COLUMN` 不支持 `IF NOT EXISTS`，必须先查 pragma。）

同步协议要把 `priority` 带上（pull/push 的字段列表里加）。

### 2.4 录入流程改造

录入页在「AI 解析确认 / 入库」这一步之前，增加一行：

```
优先级：[1 低] [2] [3 中 ✓] [4] [5 高]      ← 单选，默认 3
说明：优先级高的词会先被背诵环节抽到
```

- 存到本批次，入库时写入每个词的 `word.priority`
- 预设词库（4级/6级）导入时同样可以选择优先级

### 2.5 冲突处理（用户明确要求）

入库时逐个检查：

| 情况 | 处理 |
|---|---|
| 词不存在 | 正常插入，写入本次优先级 |
| 词已存在，**优先级相同** | 静默更新其他内容（义项等），不打断 |
| 词已存在，**优先级不同** | **弹出询问**：「单词 X 已存在（当前优先级 3，本次 5），是否覆盖优先级？」→ 三个选项：**覆盖为 5** / **保留 3** / **应用到本次所有冲突**（批量选择） |

- 询问框要显示冲突总数「共 12 个词优先级冲突」
- 提供「全部覆盖」「全部保留」快捷按钮，避免一个个点
- 用户选择后记录到本次会话，不再重复问

### 2.6 抽词：绝对优先（背诵环节）

**在 R3 阶段实现**（本阶段先把数据字段和录入做好，抽词改造放 R3，避免一次改太多）。

本阶段只需保证：
- `word.priority` 字段正确写入、正确同步
- 列表页能显示（R3 会加列和筛选）

## 验收标准

### 格式拓展
1. `npm install mammoth pdfjs-dist` 成功，`npx tsc --noEmit` 零报错，`npm run build` 通过
2. 准备三个测试文件：`test.txt`（10 行单词）、`test.docx`（含表格和列表）、`test.pdf`（有文本层的，可打印网页生成）
3. 分别上传：
   - txt → 解析出正确文本
   - docx → 解析出文本，单词和释义没有糊成一团
   - pdf → 解析出文本，**页码顺序正确**
4. **扫描件测试**：用一张图片转的 PDF → 提示"无文本层/疑似扫描件"，不崩溃、不静默入库空数据
5. 多选 3 个文件 → 依次解析，各自显示状态
6. 解析后的文本能进入编辑框 → 能正常走 AI 解析 → 正常入库
7. **动态加载验证**：打开录入页时 Network 面板里**没有**加载 mammoth/pdfjs；选了 docx 之后才加载

### 优先级
8. 录入时选优先级 5 → 入库后查数据库/列表，词的 `priority = 5`
9. 再录同一个词，优先级选 2 → **弹出冲突询问**，显示当前 5 / 本次 2
10. 选「覆盖」→ 该词变成 2；选「保留」→ 仍是 5
11. 批量冲突：一次录 5 个已存在且优先级不同的词 → 询问框显示「共 5 个冲突」→「全部覆盖」生效
12. `priority` 能正确同步到云端（换设备/无痕窗口能同步到）
13. 数据库迁移安全：在**已有数据的库**上跑迁移，原有数据不丢，老词的 priority 默认为 3

### 回归
14. 一期原有功能完好：背诵流程、记忆环节、复习、列表、设置、云同步
15. 二期（若已装）功能完好
