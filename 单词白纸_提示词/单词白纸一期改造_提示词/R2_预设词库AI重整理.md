# 阶段 R2：预设词库（4级/6级等）用 AI 重新整理义项

> 前置：R1 已完成并 commit。已贴 `00_同步版主提示词_每次必贴.md`。

---

## 背景

现在的预设功能（点「4级」「6级」直接导入一批词）**很方便**，但问题是：
- 义项**切分太粗或太碎**（比如多个意思挤成一坨，或者把一个意思拆成好几条）
- **近义词没有归类**（"高兴/快乐/愉快"被当成三个独立义项，而不是"高兴"的代表义项 + 近义词）

**目标**：对已经导入的预设词库，按项目的**标准录入规则**重新用 AI 过一遍义项。

**铁律**：**不改变优先级、不改变来源、不动任何学习记录。** 只重写义项结构和补音标例句。

---

## 一、标准录入规则（复述，供 AI 遵循）

> 这是项目阶段 03 定义的规则。因为你是新对话，这里完整复述，请严格遵守：

1. **义项合并**：含义相近的中文意思**合并为一个义项**
   - 例：「高兴 / 快乐 / 愉快」→ 合并为一个义项
   - 选定一个**代表义项**（最常用、最核心的那个），其余作为**近义词**放进该义项的 `aliases`
2. **义项拆分**：确实是不同意思的，**拆开**
   - 例：「bank → 银行 / 河岸」是两个义项，不能合并
3. **音标**：原文没有就**补全**（英式或美式均可，标注清楚）
4. **例句**：原文没有就**补一个**地道、简短的例句
5. 输出**严格 JSON**

**输出 schema**（与阶段 03 一致）：
```json
{
  "words": [
    {
      "en": "abandon",
      "phonetic": "/əˈbændən/",
      "senses": [
        { "text": "放弃", "aliases": ["抛弃", "遗弃"] },
        { "text": "离弃", "aliases": ["舍弃"] }
      ],
      "example": "He abandoned his car in the snow."
    }
  ]
}
```

## 二、任务

### 2.1 入口与范围

在**录入页**加一个分区：「已有词库整理」

- 按钮：**「用 AI 重新整理义项」**
- 点开后选择范围（下拉）：
  - 某个来源（会列出所有 source，如「4级」「6级」）
  - 全部未整理过的词
  - 全部词（谨慎，会重跑所有）
- 默认选中「上次导入的预设来源」

### 2.2 处理流程

```
选中 N 个词
  → 分批（每批 50 个）
  → 逐批调用 AI：把这批词的【当前义项 + 音标 + 例句】发给它
    → 要求它按标准规则重新切分/合并/归类
  → 拿到新结果，与旧结果 diff
  → 展示差异预览（前 20 条）
  → 用户确认 → 写库
```

### 2.3 `src/services/reparse.ts`（新增）

```ts
export interface ReparseOptions {
  words: Word[];
  onProgress: (done: number, total: number) => void;
  cfg: AiConfig;
}

export interface ReparseDiff {
  wordId: string;
  en: string;
  before: { senses: Sense[]; phonetic?: string; example?: string };
  after:  { senses: Sense[]; phonetic?: string; example?: string };
  changed: boolean;
}

export async function reparseWords(opts: ReparseOptions): Promise<ReparseDiff[]>;
```

**提示词要点**（写进 `reparseWords` 的 system prompt）：
- 「以下是若干单词的当前义项数据。请按规则重新整理：
  ①含义相近的合并为一个义项，选一个代表，其余作为近义词(aliases)
  ②确实不同的意思拆开
  ③音标/例句缺失则补全
  ④**只调整义项结构、音标、例句，不要新增或删除单词**」
- 「输出严格 JSON：`{ "words": [{ "en": "...", "phonetic": "...", "senses": [{"text":"代表义项","aliases":["近义词"]}], "example": "..." }] }`」
- 把当前数据作为 user message 一起发过去

**健壮性**：
- 分批 50，批间间隔 500ms（避免限流）
- 单批失败 → 重试 1 次 → 仍失败则跳过该批并记入错误列表，**不中断整体**
- 断点续传：已处理进度存 sessionStorage，刷新后可继续
- AI 返回缺词（某些词没在结果里）→ 保留原样，不删除

### 2.4 差异预览 UI

整理完成后展示：

```
整理完成：共 500 词，其中 312 词有变化

┌────────────────────────────────────┐
│ abandon                            │
│ 旧：放弃 | 抛弃 | 遗弃 | 舍弃        │  ← 4 个平铺义项
│ 新：①放弃（抛弃、遗弃）②舍弃         │  ← 2 个义项，带近义词
└────────────────────────────────────┘
（展示前 20 条，其余折叠）

[取消]  [应用这 312 处修改]
```

- 每条显示：单词 + 旧义项（灰色，删除线感） + 新义项（高亮）
- 可以逐条勾选是否应用
- 「应用」→ 批量写库（`updateSenses`），**只改 senses/phonetic/example**

### 2.5 铁律检查（写进代码注释）

应用修改时**绝不能碰**：
- `priority`（R1 刚建好的优先级）
- `source` / `sourceId` / `rawSources`
- `status`（未背/已背/已斩）
- `attrs`（needSpell / failCount / reviewCount / lastReviewAt / learnedAt / reviewPriority）
- `id` / `createdAt`

只写：`senses` / `phonetic` / `example` / `updatedAt`

## 验收标准

1. `npx tsc --noEmit` 零报错，`npm run build` 通过
2. 选一个预设来源（如「4级」，建议先用 20~50 词的小来源测试）→ 点「重新整理」
3. **进度与断点**：处理中显示进度；刷新页面后能继续（或至少不丢已处理结果）
4. **效果验证**（重点）：
   - 找一个原本"高兴/快乐/愉快"平铺成 3 个义项的词 → 整理后变成 **1 个义项 + 2 个近义词**
   - 找一个"bank 银行/河岸"这类 → 仍然是 **2 个独立义项**（不能被错误合并）
   - 缺失音标/例句的词 → 补上了
5. **差异预览**：显示旧/新对比，能逐条勾选
6. **铁律验证**（最重要）：
   - 找一个已背过、有复习记录的词 → 整理后 `attrs`（复习次数、优先度、掌握度）**完全没变**
   - 找一个优先级为 5 的词 → 整理后 `priority` **仍是 5**
   - 来源标记**不变**
7. 单批失败时：跳过并继续，最后列出失败批次，不崩溃
8. 整理后云同步，其他设备能看到新义项
9. 回归：一期原有功能完好；二期（若已装）完好
