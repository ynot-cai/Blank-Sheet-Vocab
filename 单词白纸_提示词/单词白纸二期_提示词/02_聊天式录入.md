## 任务

### 1. `src/services/kcPrompts.ts` —— 三套提示词模板（集中管理）

#### 1.1 录入解析提示词（`IMPORT_PROMPT`）

**System**：
> 你是一个英语教师，擅长把学生模糊的"我这块不行"整理成结构化的知识点卡片。
> 输出**严格 JSON**，不要 markdown 代码块，不要解释。

**User**：用户消息 + 已有知识点标题列表（用于避免重复）

**输出 schema**：
```json
{
  "cards": [
    {
      "title": "定语从句：关系代词 vs 关系副词",
      "summary": "一句话摘要",
      "blocks": [
        { "type": "heading", "content": "核心区别" },
        { "type": "text", "content": "关系代词在从句中作主语/宾语；关系副词作状语" },
        { "type": "example", "content": "This is the house where I lived.", "translation": "这是我住过的房子。" },
        { "type": "list", "items": ["先行词是地点且从句完整 → where", "先行词是地点但从句缺主语 → which/that"] },
        { "type": "table", "rows": [["关系词","先行词","从句成分"],["where","地点","状语"],["which","物","主语/宾语"]] },
        { "type": "tip", "content": "易错：先行词是地点不一定用 where，要看从句缺什么成分" }
      ],
      "examTags": ["fill", "choice"],
      "examLoad": { "types": ["fill", "choice"], "estMinutes": 4 }
    }
  ]
}
```

**规则（写进提示词）**：
1. **自动拆分**：用户说一个模糊的点，你要拆成**若干个**独立、完整的知识点（通常 2~5 个）。每个卡片是一个"最小完整知识片"
2. **内容完整**：每个知识点要讲透——定义、规则、例句、易错点，不要只给一句话
3. **块类型选择**：按内容性质选合适的 type，让卡片结构清晰；易错点用 `tip`，对比用 `table`，多个要点用 `list`
4. **考核标签**：从 `fill / sentence / choice / judge` 里选**该知识点适合的 1~3 种**（这就是"有多少种考法"）
5. **出题量**：`examLoad.estMinutes` 控制在 **3~5 分钟**，`types` 给出具体题型组合（如语法填空+选择题约 4 分钟）
6. **例句必须真实、地道**，配中文翻译
7. 只输出 JSON

**降级**：AI 返回不是合法 JSON 时，尝试提取第一个 `{...}` 块再 parse；仍失败则给用户明确提示"AI 返回格式异常，请重试或手动录入"。

### 3. `src/ui/pages/KcImportPage.ts` —— 聊天界面

**布局**：
```
┌────────────────────────────────────┐
│  对话区（上方，可滚动）              │
│  ┌──────────────┐                  │
│  │ 我在定语从句这块不行  │ ← 用户气泡 │
│  └──────────────┘                  │
│  ┌──────────────────────────┐      │
│  │ AI：我帮你拆成了 3 个知识点  │ │ ← AI 气泡，内嵌卡片预览
│  │  [卡片1 标题]  预览  采纳 ✓ │ │
│  │  [卡片2 标题]  预览  采纳 ✓ │ │
│  │  [卡片3 标题]  预览  采纳 ✓ │ │
│  └──────────────────────────┘      │
├────────────────────────────────────┤
│ [输入框：说说你哪里不行…]  [发送]   │
└────────────────────────────────────┘
```

**交互流程**：
1. 用户输入自然语言 → 发送
2. 显示"AI 正在整理…"loading（可取消）
3. AI 返回后，每条消息下展示**卡片预览列表**：
   - 标题 + 摘要
   - 标签 chip（考核方式）
   - 「预览」→ 展开看完整块渲染（用 `renderBlocks`）
   - 「采纳」→ 加入待入库区
   - 「编辑」→ 跳编辑器（阶段 03 的 BlockEditor，本阶段可先只改标题/标签）
   - 「丢弃」
4. 底部固定操作栏：「全部采纳」「清空」「**确认入库（N 张）**」
5. 确认入库 → `dao.kc.bulkUpsert` → Toast「已入库 N 张卡片」→ 询问"继续录入 / 去列表"

**细节要求**：
- 对话历史存会话内（不落库，刷新即清），但**已采纳的卡片要落库**
- 已有知识点标题列表从 `dao.kc.getAll()` 取，传给 AI 避免重复生成
- 输入框支持 Enter 发送、Shift+Enter 换行
- AI 失败时：气泡内显示错误 + 「重试」按钮
- 提供「手动新建空白卡片」入口（跳过 AI）

## 验收标准

1. `npx tsc --noEmit` 零报错，`npm run build` 通过
2. 输入"我在定语从句这块不行" → AI 返回 ≥2 张卡片，每张**结构完整**（有定义、例句、易错点）
3. 卡片预览能正确渲染各种块（heading/text/example/list/table/tip 都试一遍），**排版正常、不白屏**
4. **XSS 测试**：让 AI 返回含 `<script>` 的内容（可手动构造一条假响应），页面上显示为纯文本，不执行
5. 考核标签正确显示（如 fill + choice）
6. `examLoad.estMinutes` 在 **3~5** 之间
7. 点「采纳」→「确认入库」→ 卡片列表（或数据库）里能看到，字段完整
8. **不重复生成**：第二次说同一个点，AI 应提示已有相似卡片（因为传了 existingTitles）
9. AI 返回非法 JSON 时：有明确提示，不崩溃
10. **一期功能完好**（回归验证）
